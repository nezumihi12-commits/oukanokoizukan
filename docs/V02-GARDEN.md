# v0.2 記憶の庭園

## 今回の実装

アプリを開くと中央庭園がホームになります。学習・図鑑・記録タブは引き続き利用できます。属名→科名、和名→属名、属名→和名の3形式をそれぞれ1回以上完全正解すると、初開花の演出を表示し、中央庭園へ追加します。写真問題と科名列挙は開花・復習段階に影響しません。

開花済みは永久実績、鮮度は現在の記憶の投影です。不正解や時間経過で開花実績は消えません。「記憶済み」「苦手」「習熟度」の既存集計と、新しい記憶鮮度は別指標として保持しています。

植物をタップすると鮮度・段階・次回予定・初開花日が見られ、図鑑へ移動、即時復習、お気に入り固定ができます。お気に入りは庭の上部に分けて表示します。GardenState.plantZonesを用意し、将来別区画へ割り当てられてもfavoriteの植物は中央に表示できる構造です。現時点では中央区画のみです。

## 復習ルール（曖昧だった部分の実装値）

| Stage | 基準間隔 |
|---|---|
| 0 | 1日 |
| 1 | 3日 |
| 2 | 7日 |
| 3 | 14日 |
| 4 | 30日 |
| 5 | 60日 |
| 6 | 120日 |

初開花でStage 0、次回は24時間後。1日は経過時間24時間として扱い、タイムゾーンを変えても段階稼ぎにはなりません。**予定時刻を過ぎ、最後の復習から24時間以上経った回答**のみ段階・通常間隔を更新します。

- 正解：鮮度1.0へ回復。更新可能ならStageを1つ進め、新Stageの間隔で次回を設定。Stage 6は上限。
- 部分正解：回答時点の鮮度に0.45加算（上限1）。Stage維持。更新可能なら現Stageの間隔と3日の短い方で再出題。
- 不正解：鮮度に0.15加算（上限1）。更新可能ならStageを1つ戻し、翌日に再出題。早すぎる再回答ではStageを戻し続けず、必要なら既存予定を翌日までに短縮。
- 早めの正解・部分正解は鮮度だけを回復し、予定を先延ばししません。前回復習が直近24時間内の場合、回答後も復習待ちに残ることがあります。
- 端末時計が前回復習より過去へ戻った場合、復習日時・段階・鮮度の更新を無視します。通常の正答率には回答事実が残ります。サーバー時刻を使った不正対策は未実装です。

通常の基本形式クイズも、開花後は1問の結果を復習として反映します。「庭の手入れ」では1属3問をまとめ、3問目の保存時に一度だけ復習を適用します。3問の平均点が満点なら正解、0.5以上なら部分正解、それ未満なら不正解です。途中終了・強制終了では回答済みの正答率は残りますが、3問揃わなかった属の段階は更新しません。通常クイズにあるヒント・登録写真の参照は引き続き利用できます。

## 鮮度と優先度

memoryFreshnessはfreshnessUpdatedAt時点の基準値です。表示時は `基準値 × 0.65^(経過秒 / 現Stageの基準秒)` で減衰させ、0〜1に収めます。次回日時と鮮度は別に管理するため、部分正解の早めの再出題でも減衰の基準Stageを変えません。

| 鮮度 | 投影 |
|---|---|
| 0.8以上 | 鮮明 |
| 0.6以上 | 少し退色 |
| 0.4以上 | セピア寄り |
| 0.2以上 | モノクロ |
| 0.2未満 | モノクロ＋透明度38% |

彩度・色乗算・透明度を植物全体にかけます。状態別の画像は生成しません。色だけで判断する必要がないよう、各カードに記憶状態の文字も表示します。動きを減らす設定では復習回復・開花のアニメーションを抑えます。

復習予定を迎えた全属から、鮮度0.2未満 → 前回不正解 → 予定超過が長い → Latin IDの順で並べ、ホームには先頭5属までを表示します。全件画面では「復習時期」「少し遅れ（予定超過24時間以上）」「記憶がかなり薄い（鮮度0.4未満）」に分類。全件連続ボタンは開始時点の全対象を出題し、5件制限はありません。

## 既存データの移行

保存形式を1から2へ更新します。v1のStudyRecordから3形式のcorrect > 0を読み、クリア状態へ変換。すでに全クリアの属はv0.2への移行時を初開花日として登録し、翌日から復習を始めます。元データには本当の初開花日時がないため、過去の日付を推測しません。移行時は大量の開花演出を出しません。

元の正答率・履歴・日別回答数・写真・位置・既存garden/character情報を残します。最初のv1ファイルを`state-v1-before-v2.json`として保存してから、新形式を原子的に書き込みます。再起動で開花日やStageをリセットしません。v1の写真込みバックアップも復元可能です。v2のバックアップはv0.1へ戻せません。

## Core v0素材

共有会話 https://chatgpt.com/share/6abcd6ba-645c-83e8-a814-7393779b15b4 からSVG生成コードと科別・属別描画案を取得。骨格12、葉14、花18、花序10を復元し、制作原本を`Art/CoreV0`、iOS用PNGをAssets.xcassetsに保存しました。描画定義は植物データから分離した`plantRenderDefinitions.json`に全307属分を収録しています。

元描画案の部品分類とCore v0の部品数は一致しないため、近い部品に割り当てています。`Art/render-plan.json`に元の記述と割り当てを記録。属固有アクセントは仮の果実・つる・葉脈で、最終アートでも同定用画像でもありません。シダなどの「開花」は学習達成を示す呼び名で、花なしとして描画します。幽香の正式画像・台詞・イベント本文は未収録です。

`GardenZone` / `HabitatDefinition` / `Observation` / `CharacterEvent`は将来用モデルとして追加。区画の開放・自動移植、写真登録の自動化、キャラクターの正式イベントは未接続です。

## 更新手順

基準リポジトリ: https://github.com/nezumihi12-commits/oukanokoizukan

比較元コミット: `9d636ba6896dce061b918fb4951e3facb5f7a9b7`。今回の環境では公開読み取りまで確認できました。GitHubへのログイン・書き込み接続はなく、v0.2をpushしたりActionsを実行したりしていません。

1. v0.1アプリの「記録」から写真込みバックアップを作成し、アプリ外へ保存。
2. 完全版ZIPのHanazukanフォルダー内のファイルをリポジトリへ上書き。素材ファイルが多いのでGitHub Desktopが扱いやすいです。**既存`.github/workflows/ios.yml`は変更不要**です。

4. 最後のコミットに対応するActions **Build and test iOS** が成功したら、新しいIPAをダウンロード。
5. 同じApple Account・Bundle IDでSideStoreから上書き導入。アプリを削除せず更新してください。英字の`Hanazukan`表示名は前回の署名エラー対策のままです。
6. 初回起動で以前の成績と写真を確認し、下のv0.2チェックを実施。

## v0.2実機チェック

- [ ] 旧版の3形式クリア属が開花済みで庭にあり、成績・写真が残る。
- [ ] 未開花の属で3形式をクリアすると一度だけ開花演出。写真問題だけでは開花しない。
- [ ] 開花直後はStage 0・次回翌日。即時復習で色彩は戻るがStageは進まない。
- [ ] 次回予定後の3問復習で正解ならStage +1。不正解・部分正解では指定どおり回復・再出題。
- [ ] おすすめは最大5属、一覧と全件連続では6属以上を処理できる。
- [ ] お気に入りを付けて庭上部に固定し、再起動・バックアップ復元後も残る。
- [ ] 5段階の退色表示と文字ラベル。開花実績は薄れても残る。
- [ ] 復習途中で終了しても採点済み成績が残り、未完了3問組はStage更新しない。
- [ ] 図鑑検索・写真追加削除・現在地・バックアップ・通常クイズに回帰がない。

日付を待たずに確認する境界・退色・24時間制限は`ReviewTests.swift`に自動テストを用意しています。端末の時計変更を通常の試験手順にはしていません。
