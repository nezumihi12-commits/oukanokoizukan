- 庭が主役。ホーム画面は中央庭園そのもの。

- 正式復習間隔は **1 / 3 / 7 / 14 / 30 / 60 / 120日**。

- 図鑑は自由に使える。復習直前だけ主要暗記情報を伏せ、必要なら `幽香に訊く` で再学習できる。
- 開花後配置は **幽香に任せる / 中央庭園に置く / 自分で植える**。
- v1では家具自由配置を行わない。
- 本番の幽香アートは専用制作を想定し、実装は仮素材で先行する。
- ブランド方向は **Icon A / Logo A**。ヒマワリ系の一輪エンブレムと柔らかい明朝系ロゴ。

# 1. プロジェクト概要 / 体験目標

## アプリ名
**確定**
- 正式名: **千花之恋図鑑 〜Garden of memory〜**
- iOSホーム画面上の表示名: **千花之恋図鑑**

## 体験の中心
**確定**
- **本作の主役は庭である。**
- 学習・復習は独立した主目的ではなく、庭を育て、鮮やかさを維持するための中核機能として位置づける。
- 植物を覚えることで「記憶の庭園」が育ち、忘れかけた植物を復習することで、その庭の鮮やかさを維持する。
- 新しく覚えることよりも、**覚えたものを忘れずに育て続けること**に比重を置く。
- 開花まではスムーズにし、学習開始のハードルを上げすぎない。
- 庭は学習進捗の可視化・トロフィー画面であると同時に、幽香と過ごし、植物を眺め、配置を楽しむ**独立した遊び場**でもある。
- ホーム画面は中央庭園そのものとし、アプリを開いた瞬間から「庭に戻ってきた」感覚を優先する。

## 体験設計上の優先順位
**確定**
1. 庭を眺める・育てる・変化を感じること
2. 記憶を維持する復習体験
3. 新しい属を覚えて開花させる体験
4. 図鑑として調べる体験
5. 模様替え・配置・幽香との相互作用

※ 4と5は目的の違う機能であり、実装上は独立していてよい。順位は「アプリの体験中心」を示すもので、図鑑機能を制限する意味ではない。

# 2. ビジュアル / 世界観 / デザイン言語

## 基本トーン
**確定**
- ビジュアル基準は **「園芸雑誌の美しさを持った箱庭ゲーム」**。
- 画面をゲームUIで覆うのではなく、庭・植物・幽香を主役にする。
- 2.5Dの斜め見下ろしを基本とし、植物の形・花壇・水辺・小道が読める程度の奥行きを持たせる。
- 「記憶の庭園」は現実の庭の完全再現ではなく、静かで少し抽象化された庭として表現する。
- 幽香は庭内では約5頭身を基準とする。

## ファンタジー表現
**確定**
- 魔法陣、強い発光、粒子、宝石的エフェクト、常時舞う花弁等は基本的に使わない。
- 記憶状態の変化は、色・輪郭・ぼやけ・静かなノイズ等で表現する。
- 開花・区画解放等の節目でも、園芸・観察の世界から大きく外れる演出にしない。

## 色・素材感
**確定方針**
- 基調候補:
  - 深緑
  - くすんだ青緑
  - 生成り
  - 土・木・石の自然色
  - 淡い花色
- UIのアクセントとして控えめな真鍮色を使ってよい。
- **金属光沢でボタンを強く縁取る表現は避ける**。
- マットで庭の背景へ馴染む素材感を優先する。
- 可読性は背景への調和より優先し、必要なコントラストを確保する。

## UIの形
**確定**
- 大きなカード・パネルで庭を囲い込まない。
- 常設ラベルを大量に置かず、景観そのものをタップ対象として使う。
- 観察・復習系UIと、植栽編集UIは見た目と位置の両方で区別する。
- 編集トレイは園芸用の作業台・トレーを思わせる控えめな意匠。
- 図鑑・学習画面は植物標本帳・観察ノートの雰囲気を使い、庭と同じ色調へ統合する。

## 植物表現
**確定方針**
- 図鑑性を損なわない程度にデフォルメする。
- 植物は属ごとの差が読み取れ、庭景観としても成立することを優先する。
- 直接管理する植物は個別オブジェクトとして描画し、控え植物の遠景表現は簡略クラスター等へ集約してよい。
- 花や葉の動きは控えめで、風に揺れる程度の連続アニメーションを基本とする。

## 幽香の見せ方
**確定**
- 庭内では5頭身前後の全身モデル。
- 学習・会話では腰上〜太腿程度の表示へ切り替えてよい。
- 幽香を常に中央へ固定せず、庭内のCharacterAnchorを利用して生活感を出す。
- システムへ従属して常にユーザーを褒める案内役にはしない。自然な人格・反応を優先する。

## 音の世界観
**確定方針**
- BGMは静かで控えめ。フリー音源・自作・利用許諾が明確な音源を使用する。
- 環境音は風、葉擦れ、水面等の抽象度の高い自然音を中心とする。
- 鳥の鳴き声や生活感の強い足音を常時入れる必要はない。
- 「少し静かすぎる」程度の余白を許容する。

# 3. 全体ナビゲーション / ホーム導線

## 下部タブ
**確定**
下部タブは暫定的に以下の4つを採用する。
- 図鑑
- ホーム
- 庭園
- 手入れ

役割:
- **図鑑**: 307属の検索・詳細・写真・情報隠しモード。
- **ホーム**: 中央庭園そのもの。鑑賞・幽香・学習開始の起点。
- **庭園**: 各区画の一覧、解放状況、移動、植栽管理。
- **手入れ**: 正式復習、おまかせ復習、自由復習、記憶状態の確認。

## ホーム上の直接導線
**確定**
- ホームには **「咲かせる」** ボタンを置く。
  - 未開花・育苗中の属を開花へ進める学習セットアップへ遷移する。
- ホーム上に **「手入れする」専用ボタンは常設しない**。
  - 正式復習への主導線は下部タブの「手入れ」に集約する。
  - 復習が必要な時は「手入れ」タブに控えめなバッジ / 状態表示を出してよい。
  - 庭の退色植物を観察した場合は、その植物から個別復習へ直接入れる。
- これにより「手入れ」がホームボタンと下部タブで重複するのを避け、ホームのUI密度を下げる。

## ホーム左上の進捗
**確定**
- RPG的なレベル表示を主役にしない。
- ホーム上の主な進捗表示は **開花数（例: 47 / 307）**。
- 必要なら周囲に小さな進捗リング等を添えるが、庭より目立たせない。

## 景観そのものをナビゲーションに使う
**確定**
- 花壇は花壇そのものをタップ。
- 水辺は水辺そのものをタップ。
- 育苗コーナーは棚・鉢等をタップ。
- ベンチはベンチをタップ。
- 奥の道は庭園画面 / 他区画への自然な導線として使える。
- 常時ラベルや案内看板を大量に置かない。
- 初回のみ軽いチュートリアル、またはごく控えめな反応で「触れられる」ことを伝える。

# 4. ホーム / 中央庭園 / 全画面鑑賞

## 中央庭園の成長表現 / 幽香の移動

### 中央庭園の初期構造
**確定**
- 中央庭園の基本構造（小道、花壇、水辺、ベンチ、樹木スペース、育苗コーナー等）は最初から存在してよい。
- 学習進行によって庭の土木構造そのものを段階的に建設・解放する必要はない。
- 代わりに、**意図的な空白・未充足感**を残し、「ここを埋めたい」と感じる構図を作る。
- 初期状態では花壇や植栽スポットに余白が多く、植物が増えるほど庭が自然に充実して見える。
- 「庭が育つ」感覚は、設備建設よりも植物数・色彩・配置・幽香の行動・季節要素の増加で表現する。

### 幽香の移動原則
**確定**
- 幽香の移動は、ユーザーから見える時だけアニメーションさせる。
- 画面外・別タブ・別画面にいる間の移動経路を律儀に再生しない。
- 画面遷移のたびに毎回長い歩行アニメーションを挟まない。
- 幽香は内部的に `currentAnchor` を持ち、庭内のベンチ、水辺、花壇、小道、樹木スペース等のCharacterAnchor間を移動する。

### ホーム上での移動
**確定**
- ホーム画面をユーザーが見ている最中に幽香が場所を変える場合は、可能なら歩行アニメーションでAnchor間を移動する。
- 移動速度は自然で短め。ユーザー操作を長く待たせない。
- 毎回ランダムに歩き回るのではなく、一定時間経過、庭イベント、時間帯、家具・植物状態などをトリガーにする。
- 待機中は微動作（視線、姿勢、髪・服の揺れ、花を見る等）を中心にし、常時歩き続けない。

### 他タブからホームへ戻った場合
**確定**
- 別タブ滞在中に幽香の位置が変わっていても、移動経路を再生しない。
- ホームへ戻った時点で、新しいAnchorに自然にいる状態を基本とする。
- 必要なら短い「歩いてきた直後」程度の導入モーションを使ってよいが、毎回必須にはしない。
- 前回ホームを離れてから短時間しか経っていない場合は、同じAnchorに残す方が自然。

### ゾーン拡大観察への移動
**確定**
- ゾーンをタップしたら、まずカメラを対象ゾーンへズームする。
- その後、ワンテンポ遅れて幽香が画面外から歩いて入ってくる。
- これにより、ホーム上で幽香がどこにいたかに依存せず、毎回一定テンポで観察シーンを開始できる。
- 幽香は対象植物の近く、または観察用のCharacterAnchorへ移動する。
- この「画面外から入場」はゾーン観察開始の演出として共通化する。

### 編集モードへの移動
**確定**
- 観察モードから編集モードへ入る際、幽香は植物操作を邪魔しないガイド用Anchorへ短く移動する。
- ここでは長い歩行演出より、短い移動または数歩のアニメーションを優先する。
- 編集中は配置助言を行える位置に留まる。

### CharacterAnchorと家具
**確定**
- ベンチ、水辺、花壇、樹木、東屋等は一部CharacterAnchorを生成できる。
- 家具・景観の配置変更によって、幽香が取り得る行動や滞在位置が増減する。
- 例:
  - ベンチ → 座る
  - 水辺 → 水面を見る
  - 花壇 → 花を見る / 手入れする
  - 樹木 → 木陰で休む / 見上げる
- CharacterAnchorは「幽香が庭で生活している感覚」を作るためのシステムとして扱う。

## 全画面鑑賞モード

### 目的
**確定**
- ホーム画面および各庭園 / 区画画面に、UIを極力消して庭の景色へ集中できる **全画面鑑賞モード** を用意する。
- 庭が本作の主役であることを、機能面でも明確にする。

### 非表示にするもの
**確定**
全画面鑑賞モード中は原則として以下を非表示にする。
- 下部タブバー
- 開花数・進捗HUD
- 「咲かせる」等の操作ボタン
- イベントバナー
- 編集ボタン
- 通常のナビゲーションUI
- システム由来の補助ラベル

### 残すもの
**確定**
- 庭そのもの
- 植物
- 幽香
- 家具
- 水面・風・葉揺れ等の環境アニメーション
- 幽香の自然な行動
- 必要に応じて幽香の自然な発話（システム通知は表示しない）

### 入退出
**暫定**
- 通常画面に「鑑賞モード」または目のアイコン等の控えめな入口を設ける。
- 全画面鑑賞中は **画面を一度タップすると最小限の退出UIを一時表示**する。
- 退出UIは数秒後に再び隠れてよい。
- 誤操作防止のため、鑑賞モード中の通常タップではゾーン移動・編集・図鑑遷移を起こさない。
- 必要なら軽いパン / 視差 / ズームだけ許可し、最終挙動は実機で調整する。

### 設計原則
**確定**
- 鑑賞モードは「操作を隠した通常画面」ではなく、庭を眺めること自体を目的としたモード。
- UIを消すことで情報量を下げ、植物・幽香・庭の配置や微アニメーションを主役にする。

## 8 全画面鑑賞モードのズームと誤操作防止

**確定**
- ホーム画面および各庭園で利用できる全画面鑑賞モードでは、**ピンチズームを許可する**。
- 必要に応じて、ズーム中のみ限定的なパンを許可する。
- これは「植物を操作する」ためではなく、花壇や植物を近くで眺めるためのカメラ操作として扱う。
- 鑑賞モード中は、花壇・植物・水辺・ベンチ・奥の道などの通常インタラクションを無効化する。
  - 花壇をタップしてもゾーン拡大観察モードへ遷移しない。
  - 植物をタップしても個体選択しない。
  - 奥の道をタップしても庭園画面へ遷移しない。
- 鑑賞モード中のタップは、原則として**最小限の退出UI / 操作UIを一時表示するためだけ**に使用する。
- 通常モードへ戻った後に、ゾーンタップや植物選択等のインタラクションを再有効化する。
- 鑑賞モードは閲覧専用の独立した入力状態として実装し、通常のタップ判定をそのまま流用しない。

**暫定**
- ズーム倍率上限は実機確認で調整する。初期実装は概ね 2.0〜2.5倍程度を候補とする。
- 1倍へ戻す操作として、ダブルタップまたは退出時自動リセットを検討する。
- パン可能範囲は庭の描画範囲内に制限し、背景の外側が見えないようにする。

# 5. 中央庭園ゾーン構造 / 非植物オブジェクト

## 中央庭園の基本配置
**確定**
以下の構成を中央庭園の初期レイアウトとして採用する。
- 奥中央: 庭園の先へ続く小道
- 左奥: 樹木スペース + ベンチ
- 右奥: 小さな水辺
- 中央〜左手前: お気に入り花壇
- 中央〜右手前: 季節花壇
- 手前側の一角: 育苗コーナー
- 別の一角: 自由展示
- 広場の縁: 小型植物を置ける補助植栽スペース
- 画面下端はUI安全領域を優先し、前景植物を巨大化させない

## 配置密度
**確定**
- 中央庭園は「植物を見せること」を最優先する。
- 植物同士、幽香、UI、景観オブジェクトが重なりすぎないよう、意図的な余白を残す。
- 空白は欠点ではなく、「ここを埋めたい」と感じさせる成長動機として利用する。
- 植物が増えるほど庭が自然に充実して見える構成を目指す。

## 非植物オブジェクトの扱い
**確定**
- v1では、**植物以外の家具・装飾品をユーザーが自由配置する機能は実装しない**。
- 理由:
  - 中央庭園の表示密度が高く、植物・幽香・UIの可読性を優先するため。
  - 家具自由配置まで加えると、衝突判定・CharacterAnchor・選択精度・画面密度の管理が大きく複雑化するため。
  - 本作の主役は植物であり、家具配置は必須体験ではない。
- ベンチ、水鉢、園芸棚、標識、鉢、灯り等の景観オブジェクトは**固定またはシステム管理の背景／設備**として配置してよい。
- これらの一部はCharacterAnchorを持ち、幽香の行動に利用できる。
- 将来的に家具配置を追加できる余地は残すが、初期実装のAcceptance Criteriaには含めない。

## 自由展示ゾーンの意味
**確定**
- 「自由展示」は植物を自由に選んで見せるためのゾーンであり、家具自由配置ゾーンではない。
- お気に入り花壇とは別に、サイズ・季節・分類に縛られず植物を置ける柔軟な展示枠として扱う。

# 6. ゾーン拡大観察モード

## 目的
**確定**
- ゾーン拡大観察モードは、ホームの「景色を眺める」状態と、編集モードの「配置を変える」状態の中間に位置する。
- このモードの主目的は、**そのゾーンの植物を近くで観察し、個々の植物を選択し、図鑑・復習へ自然につなぐこと**。
- 編集操作はこのモードでは行わない。編集は明示的な「植栽編集」入口からのみ開始する。

## 入口とカメラ遷移
**確定**
- 通常ホームでゾーン（花壇、水辺、育苗コーナー等）をタップすると開始する。
- まずカメラが対象ゾーンへズームする。
- ズーム完了後、ワンテンポ遅れて幽香が画面外から歩いて入ってくる。
- ホーム上での幽香の元位置には依存せず、ゾーン観察開始時のテンポを共通化する。
- 観察モード中は対象ゾーン内に限って軽いパン／ピンチズームを許可する。
- 可動範囲はゾーン境界内に制限し、背景外や隣接ゾーンへカメラが抜けないようにする。

**暫定**
- ズーム遷移: 約0.3〜0.5秒
- 幽香入場の間: ズーム後0.2〜0.4秒程度
- 幽香の歩行入場: 約0.8〜1.2秒
- いずれも実機でテンポ調整し、ユーザー操作を長く待たせない。

## 初期状態
**確定**
- ゾーンへ入った直後は、植物は未選択状態。
- 植物名や詳細カードを一斉表示しない。
- スロット番号・配置枠・編集用ガイドも表示しない。
- 幽香は観察用CharacterAnchorへ移動し、植物を眺める・視線を向ける等の軽い待機動作を行う。
- 必要でなければ幽香は入場直後に必ず喋る必要はない。

## 植物の選択
**確定**
- 観察モードでは、ゾーン内の個々の管理対象植物をタップして選択できる。
- 同時に選択できる植物は1つ。
- 選択対象は「1輪」ではなく、アプリ内で1個体／1属表示として管理している植物オブジェクトまたはクラスター。
- 選択時:
  - 対象植物は通常彩度を維持。
  - 輪郭をわずかに強調する。
  - 必要ならごく弱い影・コントラスト差を加える。
  - **魔法的な発光・粒子・オーラは使用しない。**
- 非選択植物:
  - 同ゾーン内は概ね15〜25%程度の存在感まで薄くする。
  - 他ゾーンが画面内に見切れている場合はさらに低い存在感でよい。
- 地形・花壇縁・水面・固定家具は消さず、少し暗く／低コントラスト化する程度。
- 幽香は通常表示を維持する。
- 空白部分をタップすると選択解除できる。
- 観察モード中の長押しでは植物を移動しない。移動は編集モード専用。

## 情報の表示位置
**確定**
- 情報ポップアップを植物の真上には表示しない。
- 理由: 他の花や葉を覆い、植物観察の視認性を落とすため。
- 植物選択時の情報は、**幽香の近くに配置する専用情報領域**へ表示する。
- 幽香の台詞吹き出しと、数値・状態を表示するシステム情報UIは分離する。
  - システム情報UI: 属名、記憶状態、次回復習等。
  - 幽香の吹き出し: その状態に対する自然な反応・コメント。
- 幽香を「状態値72%です」のような数値を読み上げるシステム音声役にはしない。
- 選択植物と情報UIが重ならないよう、幽香＋情報領域は画面左右の空き側へ適応配置してよい。

## 通常時に表示する情報
**確定方針**
復習期限に達していない植物を選択した場合、観察モードでは最低限以下を表示してよい。
- 属名 / 属和名（表示形式は図鑑データに準拠）
- 記憶状態（言葉による状態表示）
- 次回手入れ目安
- 写真登録済み / 観察済みの簡易表示
- 開花済みであることは庭に存在している時点で自明なので、強調表示は不要

**確定**
- 科名や詳細説明など、図鑑レベルの情報を観察画面に大量表示しない。
- 詳細は「図鑑を見る」へ逃がす。
- 観察画面は庭を眺める体験を壊さない情報量に留める。

## 記憶状態UI
**確定**
- 庭上の見た目は、復習期限までは原則正常に保ち、期限超過後の `overdueSeverity` に応じて悪化させる。
- 観察画面では内部数値そのものより、5段階の状態ラベルを優先する。
  1. 安定
  2. 手入れどき
  3. 乾き始め
  4. 色褪せ
  5. かなり曖昧
- 必要なら補助的に細いゲージを表示してよい。
- 期限前は `手入れまであと約2日`、超過後は `手入れ予定から約3日` 等の時間情報を小さく表示してよい。
- 生の百分率は通常UIに出さない。

## 復習期限に達した植物を選んだ場合
**確定**
- 復習時期に入っている植物を選択した直後は、**復習問題の答えになり得る主要暗記情報を自動表示しない**。
- まず「思い出す機会」を提示する。
- 庭上の植物ビジュアルそのものは見えていてよい。
- 幽香は自然な反応として問いかけをしてよいが、正式台詞は後で決める。
- 下部アクションは概ね:
  - **思い出す / 復習する**
  - **図鑑を見る**
  - **閉じる**
- `復習する` → 正式復習へ。
- `図鑑を見る` → 復習保護された図鑑詳細へ。ページを開いただけでは `relearnedAt` は付かない。
- 伏せた主要暗記情報を `幽香に訊く` で確認した時点で `relearnedAt` を記録し、その属は約24時間おまかせ復習から外す。

## 観察画面の下部アクション
**確定**
植物選択時の基本アクション:
- 図鑑を見る
- 復習する（復習対象外なら非表示または低優先）
- 閉じる / 選択解除

**確定**
- 「植栽編集」は上記アクション群と同列に置かない。
- 編集は画面右上、園芸道具アイコン、独立した色・位置などで**別系統の入口**として表現する。
- 観察・復習系ボタンと編集ボタンは、見た目・配置の両方で区別する。

## 戻る操作
**確定**
- 左上に共通系の戻るボタンを置く。
- ゾーン拡大観察から戻るとホーム／直前の庭画面へカメラが引いて戻る。
- 植物選択中でも戻るボタンは機能する。
- 選択解除専用の「閉じる」は、ゾーン観察そのものを終了せず、植物選択だけ解除する。

## 観察モードと全画面鑑賞モードの違い
**確定**
- 全画面鑑賞モード:
  - 見る専用。
  - ズーム・限定パン可。
  - 花壇／植物タップで観察画面へ遷移しない。
  - 個体選択しない。
- ゾーン拡大観察モード:
  - 個々の植物を選択できる。
  - 図鑑・復習・編集への入口がある。
  - UIは存在する。
- この2モードを混同しない。

# 7. 編集モード

## 目的
**確定**
- 編集モードは、ゾーン内の植物配置を変更するための専用状態。
- 観察モードとは明確に分離する。
- 編集開始時に別画面へ飛ばず、**観察していたゾーンのカメラ位置・景観をそのまま維持**して編集状態へ移行する。
- 編集中は植物配置に集中できるUIへ切り替え、図鑑・復習系の操作は一旦引っ込める。

## 入口
**確定**
- ゾーン拡大観察モードの右上等に、独立した `植栽編集` ボタンを置く。
- 観察系アクション（図鑑を見る / 復習する / 閉じる）とは色・位置・アイコンで区別する。
- アイコンは移植ごて、園芸ばさみ、植木鉢等の園芸道具を候補とする。
- 金属光沢の強いボタンにはしない。庭と馴染むマットなUIを使う。

## 編集開始時
**確定**
- 植物選択状態がある場合は解除する。
- 幽香は編集操作を邪魔しないガイド用CharacterAnchorへ短く移動する。
- 植栽スポットを表示する。
- 画面下部から植物トレイを表示する。
- 既存植物の配置、空きスポット、スロットサイズを視覚化する。
- 編集前の配置状態をスナップショットとして保持し、完了までは本保存しない。

## 植栽スポット
**確定**
- スポットは通常時には見せず、編集時だけ表示する。
- 各スポットはサイズクラス（S / M / L / XL）と配置タイプを持つ。
- 表示は格子状のマス目ではなく、庭の景観に馴染む半透明の輪郭・土面・小さな札等を使う。
- スポット番号は内部で持つ。
- ユーザー向けには必要な時だけ小さく番号表示してよい。
- ドラッグ時は置ける候補だけを強調する。
- 置けない候補は弱く無効化表示する。

## 下部植物トレイ
**確定**
- 画面下部に横スクロール式トレイを表示する。
- トレイは「作業台の引き出し」や「園芸用トレー」を思わせる、背景に馴染むマットなデザイン。
- 豪華な金属フレーム、発光、ファンタジー装飾は使わない。
- 植物カードには最低限:
  - 小さな植物サムネイル
  - 属名 / 表示名
  - サイズ
  - 現在の配置状態
  - 必要なら適性の簡易表示
- トレイ内カテゴリ候補:
  - 未配置
  - このゾーン向き
  - すべて
  - お気に入り
  - 現在配置中
- 並び順は「このゾーンに向くもの」を優先してよい。
- 適性が低い植物も、完全禁止でなければ `すべて` から選択できる。

## 操作
**確定**
- タップ: 植物カード / 植物を選択。
- 長押し（目安0.4〜0.6秒）: 持ち上げ開始。
- 長押し後そのままドラッグ: 植物移動。
- 指を離す: 配置確定（仮状態）。
- 持ち上げ開始時に軽い触覚フィードバック。
- 配置候補へ近づいたら弱い吸着を行う。
- 強制的に大きく位置補正しない。
- 無効位置へ離した場合は元の位置 / トレイへ戻す。
- 編集中に長押し誤作動が頻発しないよう、タップと長押しの閾値を実機調整する。

## 配置判定
**確定**
配置判定は、単一の「良い / 悪い」評価にせず、少なくとも以下の独立した軸で扱う。

### A. 物理配置
- **余裕あり**: 占有範囲・前後関係に十分な余裕がある。
- **収まる**: 問題なく配置できる標準状態。
- **密植気味**: 他植物との距離が近いが、見た目上の選択として配置は許可する。
- **配置不可**: スロットサイズ不一致、完全衝突、UI安全領域への侵入等。配置を確定しない。

### B. 環境適性
- **好適**: その植物に特に向くゾーン / スポット。
- **適応可**: 最適ではないが、ゲーム上は自然に置ける。
- **環境違い**: 生育タイプと場所の性質が大きく合わない。
- **配置不可**: 水生植物を乾燥花壇へ置く等、表現上成立しない組み合わせ。

### C. 景観バランス
- 高さ、前後関係、周囲の密度から見た景観上の助言。
- これは原則として強制制限ではなく、幽香のコメントや軽い表示に利用する。

**設計原則**
- 「やや無理」のような包括的・否定的ラベルは使用しない。
- ユーザーが判断できるよう、**何が気になるのか（密度 / 環境 / サイズ / 景観）を具体的に示す**。
- 物理的に成立し、環境的にも許容範囲なら、多少密でも配置を許可する。
- アプリが過剰に自動修正せず、ユーザーの美的判断を尊重する。

## 幽香の配置助言
**確定**
- 配置判定の理由を、可能な限り幽香の自然な台詞で伝える。
- 例となるイベントID:
  - `placementGood`
  - `placementCrowded`
  - `placementBadHabitat`
  - `placementBlocked`
  - `placementBeautiful`
  - `placementFavorite`
- 正式台詞本文は後で決める。
- 同種の助言は短時間に連続表示しない。
- 重要な配置不可だけは、幽香の台詞に加えて視覚的な無効表示も併用する。
- 幽香はユーザーへ従属して褒め続ける存在ではなく、自分の感覚で率直に助言する。

## 植物を外す / 入れ替える
**確定**
- 植物をゾーン外へ「削除」する概念は使わない。
- 外した植物は **未配置トレイ** へ戻す。
- 既存植物の上へ別植物をドラッグした場合:
  - 入れ替え候補として扱う。
  - 既存植物は未配置へ戻す、または交換確認を出す。
- 中央庭園が満杯の状態で新しい開花植物を置く場合:
  - `入れ替える`
  - `配置を編集する`
  - `幽香に任せる`
  の逃げ道を必ず用意する。

## 未配置トレイ
**確定**
- 未配置は「育苗コーナー」とは別概念。
- 育苗コーナー = 開花前。
- 未配置トレイ = 開花後だがまだ本配置されていない植物。
- `幽香に任せる` を選んだ植物は原則として未配置に長期間残さない。
- `自分で植える` を選んで中断した場合などに未配置へ置く。

## 編集中のカメラ
**確定方針**
- ゾーン内に限ってパン / ピンチズームを許可する。
- トレイやボタンの下に編集対象が隠れないようSafe Areaを考慮する。
- UI表示によって見えない領域へ植物を置けないようにする。
- カメラ可動範囲はゾーン内に制限する。

## 完了 / 破棄 / Undo
**確定**
- `完了` で仮配置を正式保存。
- 左上 `戻る` で編集を終了しようとした時、変更がある場合は:
  - 変更を破棄して戻る
  - 編集を続ける
  を確認する。
- 保存が短時間なら専用ロード画面は出さない。
- 保存・再計算が明確に0.5秒以上かかる場合のみ、`植え替えています…` の小さなオーバーレイで操作を一時ロックする。
- 保存後は観察モードへ戻り、直前と同じゾーンカメラを維持する。
- 直後5〜10秒程度の `元に戻す` を検討する。

## 自動整頓
**暫定**
- 将来的に `自動整頓` を追加可能。
- 初期実装では必須ではない。
- 実装する場合は:
  - 自然風
  - 整形式
  - 群生風
  などのプリセットを検討できる。
- 手動固定した植物は自動整頓対象から外す。

# 8. 配置ルール / スロット / サイズ

## 設計方針
**確定**
- スロット数・サイズ配分・植物占有範囲は、後から数値調整しやすい**データ駆動**で実装する。
- SwiftUIビュー内へ固定値を直接埋め込まず、ゾーン定義・植物定義から読み込む。
- したがって、初期値を完全に詰め切ることより、**後からパラメータ変更だけで調整できる構造**を優先する。

## 植物サイズ
**確定**
基本サイズクラス:
- S
- M
- L
- XL

必要に応じて各クラスへ占有幅の補正値を持たせる。
例:
- narrow
- normal
- wide

サイズは見た目の高さだけでなく、主に以下に利用する。
- 植栽スポット適合判定
- 周囲との衝突 / 密度判定
- 前景・中景・後景の配置補助
- カメラ拡大時のタップ領域

## ゾーン側スロット
**暫定**
中央庭園の初期案:
- お気に入り花壇: L×1 / M×2 / S×3
- 季節花壇: L×1 / M×2 / S×3
- 水辺: L×1 / M×1 / S×2
- 自由展示: L×1 / M×2 / S×2
- ベンチ周辺: M×1 / S×2
- 樹木スペース: XL×1〜2
- 広場の縁: M×1 / S×2〜3

これらは**完成固定値ではない**。
実機で植物モデルの大きさ・タップしやすさ・幽香との重なりを確認し、設定値だけ変更して調整する。

## 実装要件
**確定**
ゾーン定義には最低限以下を持たせる。
- `slotID`
- `sizeClass`
- `position`
- `zLayer / depth`
- `placementType`
- `allowedFootprint`
- `interactionSafeArea`
- 必要なら `environmentTags`

植物定義には最低限以下を持たせる。
- `sizeClass`
- `footprintScale`
- `heightClass`
- `placementTypes`
- `environmentTags`
- `renderScale`

## 調整原則
**確定**
- 数値調整だけで「少し詰める / 広げる / 大きくする / 小さくする」が可能であること。
- スロット調整のために画面ロジックを書き直す設計は禁止。
- 最終値は実際の植物アセットが揃ってから調整する。

# 9. 幽香のCharacterAnchor / 行動

## 目的
**確定**
- 幽香をホーム画面に固定配置された「案内キャラ」ではなく、**庭の中で過ごしている住人・管理人**として扱う。
- 庭の景観・植物・固定設備に紐づく `CharacterAnchor` を用意し、幽香はAnchor間を移動して行動する。
- 幽香の移動・行動は庭の雰囲気を豊かにするためのものであり、ユーザー操作を待たせたり、常時動き続けたりしない。

## CharacterAnchor の基本構造
**確定**
各Anchorは最低限以下の情報を持つ。

- `anchorID`
- `zoneID`
- `position`（ゾーン内の正規化座標を推奨）
- `zLayer / depth`
- `facingDirection`
- `allowedActions`
- `requiredSceneState`
- `requiredObjectID`（ベンチ等、必要な場合）
- `minimumClearance`
- `uiAvoidanceArea`
- `selectionWeight`
- `minDwellTime`
- `maxDwellTime`
- 必要なら `entryDirection`

Anchor位置は画面コードへ直接埋め込まず、庭レイアウト定義から変更可能にする。

## 初期Anchor種別
**確定**
v1では最低限、以下を用意する。

### 通常立ち
- 中央広場
- 小道脇
- 花壇脇

### 観察
- お気に入り花壇を見る
- 季節花壇を見る
- 育苗コーナーを見る
- 水辺を見る
- 樹木を見上げる

### 休憩
- ベンチに座る
- 樹木の木陰に立つ / 休む

### 作業
- 花壇の手入れ
- 育苗コーナーの確認
- 水辺の様子を見る

### モード専用
- ゾーン拡大観察の入場先Anchor
- 編集モードのガイドAnchor

**将来拡張**
- 読書
- お茶
- 季節限定行動
- 写真や観察記録に反応する行動
- 新規固定設備に紐づく行動

## Anchor選択ロジック
**確定**
Anchorは完全ランダムに選ばない。

選択優先度は概ね以下の順に考慮する。
1. 現在のモードで必須のAnchor
2. 発生中イベントに必要なAnchor
3. 庭の状態に反応するAnchor
4. 時間帯・季節・植物状態に合うAnchor
5. 通常の待機Anchor

同じAnchor・同じ行動ばかりが続かないよう、直近履歴に応じて重みを下げる。

## 移動頻度
**暫定**
- 常時歩き回らせない。
- 通常ホームでは、1つのAnchorに**数十秒〜数分**滞在する。
- 初期値候補:
  - 最短滞在 45秒
  - 標準滞在 90〜180秒
- イベントがなければ、短時間に何度も移動しない。
- 具体値は実機で「落ち着きがあるか」を見て調整する。

## ホーム表示中の移動
**確定**
- ユーザーがホームを見ている最中にAnchorを変更する場合は、可能な限り歩行アニメーションで移動する。
- 移動経路は最短の直線ではなく、必要なら小道や通行可能領域に沿わせる。
- 歩行中もUI操作はブロックしない。
- 幽香が植物やUIを大きく横切って視認性を損なう場合は、経路またはタイミングを調整する。
- 目的地到着後に対応Actionへ遷移する。

## 別画面滞在中の位置更新
**確定**
- ユーザーが図鑑・手入れ・庭園など別画面にいる間、幽香の全移動をリアルタイム再生する必要はない。
- ホームへ戻る時点で、経過時間・庭状態に応じてAnchorを再評価してよい。
- 短時間の画面往復では、原則として同じAnchorを維持する。
- 長時間離れていた場合は別Anchorにいてもよい。
- ホーム復帰時に「移動経路の再生」を強制しない。

## ゾーン拡大観察での入場
**確定**
- ゾーンタップ後、まずカメラを対象ゾーンへズーム。
- その後、幽香は**画面外から歩いて入場**する。
- ホーム上で元々どこにいたかは、この演出には引き継がない。
- 観察用Anchorまで歩いた後、対象植物・ゾーンへ視線を向ける。
- これにより、元位置に関係なく毎回同じテンポで観察開始できる。

## 編集モードでの位置
**確定**
- 編集開始時、幽香は操作対象を隠さないガイドAnchorへ移動する。
- 長い歩行演出は不要。短い移動でよい。
- 編集中は原則としてそのAnchorに留まり、配置助言を行う。
- トレイ・ボタン・植栽スポットと重ならないよう、Anchor側にUI回避情報を持たせる。

## 行動（Action）と表情の分離
**確定**
幽香の状態は少なくとも以下を分離して管理する。
- `anchorID`
- `actionID`
- `expressionID`

例:
- `anchorID = bench_left`
- `actionID = sitting`
- `expressionID = neutral`

この構造により、同じ座りポーズでも表情だけ差し替えられる。
素材が存在しない `actionID / expressionID` は、最も近い既存素材または `neutral` にフォールバックする。

## v1で必要な最小Action
**確定**
初期実装では以下を最低限とする。
- `idleStand`
- `walking`
- `lookAtPlant`
- `sitting`
- `gardening`
- `guide`

**将来拡張**
- `lookAtWater`
- `reading`
- `inspectSeedling`
- `lookUpTree`
- `seasonalAction`
- その他、必要になった時点で追加

## CharacterAnchorと固定設備
**確定**
v1では家具自由配置を実装しないため、Anchorは原則として固定設備・固定景観へ紐づける。
- ベンチ → `sitting`
- 水辺 → `lookAtWater` 相当
- 花壇 → `lookAtPlant / gardening`
- 育苗コーナー → `inspectSeedling` 相当
- 樹木 → 木陰・見上げ等

将来、家具自由配置を追加する場合のみ、家具配置に応じてAnchorを動的生成できる拡張余地を残す。

## 衝突・視認性
**確定**
- 幽香のAnchorはインタラクティブ植物の主要タップ領域を恒常的に覆わない。
- 下部タブ、HUD、学習ボタン等のUI安全領域を避ける。
- 植物の成長・配置変更によってAnchor周辺が混雑した場合、Anchorを一時無効化するか、代替Anchorを選ぶ。
- 幽香の存在によって植物の観察・編集が困難にならないことを優先する。

## 設計思想
**確定**
- 幽香は「ユーザーが呼ぶと必ず都合よく現れる従属キャラ」ではなく、庭で自分の時間を過ごしている存在として見せる。
- 一方、ゾーン観察・編集等の操作上必要な場面では、ゲーム進行を妨げない範囲で共通演出として合流させる。
- 日常時の自由さと、操作時の分かりやすさを両立する。

# 10. 幽香の発話 / イベント通知

## 基本思想
**確定**
- すべての出来事を幽香の吹き出しで順番に消化しない。
- 通知の重要度・性質に応じて、**専用案内 / イベントバナー / ポップアップ**を使い分ける。
- 幽香は通知センターではなく、庭の住人・管理人として自然に喋る。
- 何も言う必要がない場面では無理に台詞を出さない。

## 発話の長さ
**確定**
- 通常の吹き出しは1〜3行程度まで。
- 2〜3行の台詞は普通に許容する。
- 長い説明・初回チュートリアル・システム説明は、通常吹き出しへ無理に押し込まない。

## 自動消去時間
**暫定**
- 短い台詞: 約8秒
- 2〜3行程度の台詞: 約12〜15秒
- 吹き出しタップで即時に閉じられる。
- 自動消去後、次の吹き出しが必要な場合は0.3〜0.5秒程度の間を置く。
- 実機で読みやすさを確認して調整する。

## 通知レベル
**確定**

### Level A: 初回だけ丁寧に案内する重要システムイベント
例:
- 初めての開花
- 初めての定植
- 新しい庭園区画の初回解放
- 曖昧の庭の初回解放
- 初めての正式復習
- 重要な新機能の初回利用

表示方法:
- 専用の案内画面、または通常画面上に強いフォーカス演出を出す。
- 幽香を通常より大きく表示して説明してもよい。
- 必要に応じて矢印・ハイライト・操作対象の強調を使う。
- 初回はユーザーが内容を理解できるまで自動で消さない方式も可。
- **同じ説明を2回目以降は繰り返さない。**
- 2回目以降はイベントバナー、短いポップアップ、または無通知へ簡略化する。

### Level B: 庭の出来事 / 季節イベント / 解放済みイベント
例:
- 季節イベント開始
- 特定の花の季節
- 新区画に移植候補が発生
- イベントミッション
- 期間限定の庭の変化

表示方法:
- ホーム上部の**イベントバナー**を主な入口とする。
- バナー自体には短いタイトルだけを表示。
- タップすると詳細説明・イベント画面を開く。
- 幽香の長い説明を強制的に連続表示しない。
- 同時に複数イベントがある場合はバナー内で切替 / 一覧化できる。

### Level C: 操作への即時反応
例:
- 植物配置時の密植コメント
- 環境適性への助言
- 植物選択時の短い反応
- 復習結果への短い反応

表示方法:
- 幽香の通常ポップアップ。
- 即時性を優先。
- 同種のコメントは短時間に何度も出さない。
- 連続操作を妨げない。

### Level D: 雑談 / 雰囲気づくり
例:
- 季節・時間帯についての一言
- 庭を眺めての独り言
- 植物への自然な感想

表示方法:
- 低優先度の通常ポップアップ。
- 他の操作・イベントが始まったら破棄してよい。
- 後で必ず再表示する必要はない。

## 発話キュー
**確定**
- FIFOで全件を順番に表示する方式にはしない。
- Level Aは見逃さないよう保持する。
- Level Bは原則イベントバナーへ集約する。
- Level Cは現在の操作に即したものを優先する。
- Level Dは空き時間にだけ表示し、状況変化で破棄可。
- 同一カテゴリの重複イベントは圧縮・置換する。
  - 例: 「密植気味」が短時間に3回発生しても、3件分の吹き出しを貯めない。

## 表示中の台詞の扱い
**確定**
- 通常は表示中の台詞を途中で強制的に切らない。
- ただしユーザーが新しい植物を選択する、編集モードへ入る等、明確に文脈が変わった場合は、低優先度台詞を終了して現在操作に必要な反応へ切り替えてよい。
- 重要イベントの説明中に通常雑談で上書きしない。

## イベント履歴
**確定方針**
- 見逃し防止のため、イベント履歴自体は持つ。
- **ホーム画面へ常設の履歴パネルや履歴アイコンを増やさない。**
- ホームの景観・余白を優先する。
- 履歴への入口候補:
  1. イベントバナーをタップ → 「現在のイベント / 最近の出来事」
  2. `庭園` または `手入れ` 内のサブ画面
- 初期推奨は **イベントバナーから最近の出来事を開く方式**。
- 履歴は「幽香の全台詞ログ」ではなく、**庭で起きた意味のある出来事**を記録する。
  - 区画解放
  - 開花
  - 季節イベント
  - 曖昧の庭解放
  - 大きな植え替え
  - その他、再確認価値があるもの
- 日常雑談や配置助言を全件保存する必要はない。

## ホーム景観との優先順位
**確定**
- 通知UIのためにホーム画面を常時混雑させない。
- 何もイベントがない時はイベントバナーを縮小または非表示にできる。
- 全画面鑑賞モードでは、イベントバナー・通知・履歴入口をすべて非表示にする。

# 11. 植物の成長 / 育苗 / 開花

## 基本思想
**確定**
- 「開花」は全植物に共通する**ゲーム上の達成用語**として使用する。
- ただし、実際の植物モデルは植物学的・園芸的に不自然な花を無理に咲かせない。
- 各属の見た目上の成長は、生育形に合わせて表現する。

## 成長段階
**確定**
必須3形式の初回正解数に応じて進行する。

- 0形式: 未着手。庭には表示しない。
- 1形式: 育苗開始。
- 2形式: 中間成長。
- 3形式: 「開花」達成。育苗を卒業し、庭へ定植可能。

**確定**
- どの問題形式を先に正解したかと、成長段階の種類は結びつけない。
- 未クリア形式が1つ埋まるごとに成長する。
- 不正解しても、一度クリアした形式は失わない。
- 開花前の成長段階は後退しない。

## 生育形ごとの見た目
**確定方針**
- 一般的な草花:
  - 芽
  - 葉が増える
  - 蕾 / 成熟直前
  - 開花状態
- 樹木・低木:
  - 小苗
  - 枝葉が増える
  - 若木
  - 成熟した姿
- 観葉植物:
  - 小苗
  - 葉数増加
  - 特徴葉が現れる
  - 成熟株
- シダ:
  - 小さな葉
  - 葉数増加
  - 展葉
  - 成熟株
- 球根・地下茎系等:
  - その植物群に自然な中間表現を用いる。

**設計原則**
- UI上では全て「開花済み」で統一してよい。
- 見た目は属の代表的な園芸像を尊重する。

## 育苗コーナー
**確定**
- 育苗コーナーは開花前の植物専用。
- 見える表示枠は約6鉢。
- 6鉢は学習上限ではない。
- 見切れ、横スクロール、ページ送り等で追加の育苗中属を確認できる。
- 表示優先順位:
  1. あと1形式で開花
  2. 最近学習した
  3. その他
- 開花達成時に育苗コーナーを卒業する。

## 開花直後と正式復習
**確定**
- 開花学習は、答えを見ながら記憶を作ることを許容する。
- 開花直後は正式復習を要求しない。
- 初回の正式復習予定は概ね24時間後を基準とする。
- 新規学習中の予習・正答確認には `relearnedAt` を適用しない。初回正式復習は概ね24時間後から始める。
- 開花後から、記憶維持フェーズ（正式復習）が始まる。

## 写真問題との関係
**確定**
- 写真問題は必須3形式に含めない。
- 写真がなくても開花できる。
- 写真問題は別枠の復習・観察価値を持つ。

# 12. 開花後の配置 / 庭園所属 / 表示上限

## 用語階層
**確定**
本仕様では「庭園」と「ゾーン」を分けて扱う。

- **庭園**: 中央庭園、水辺、林縁、木立、温室等の大きな区画単位。
- **ゾーン**: 1つの庭園の中にある、花壇・水際・木陰・樹木スペース等の小さな植栽単位。
- **植栽スポット**: 1ゾーン内で植物を実際に表示・配置するスロット。

従来の「5〜6属程度」は、**庭園全体ではなく1ゾーンあたりの目安**とする。

## 画面上の表示数
**確定方針 / 数値は暫定**
- 1ゾーンの表示目安: 4〜6属程度。
- 1庭園全体の表示目標: おおむね12〜18属程度。
- 標準的な庭園では **約15属前後** を1つの目安とする。
- 植物サイズ・景観・幽香・UIとの干渉により、庭園ごとに上限は変えてよい。
- 樹木中心の庭園は少なめ、水辺や草原等は多めにできる。
- 数値は固定ハードコードせず、ゾーン定義と植物サイズのパラメータで調整可能にする。

## 「所属」と「表示」を分離する
**確定**
開花済み植物には少なくとも以下を別々に持たせる。

1. **庭園所属**
   - その植物がどの庭園に属しているか。
   - 幽香へ配置を任せた場合は、適性スコアと解放状況を見て決定する。
   - 手動配置時はユーザーが決める。

2. **表示ゾーン / 表示スポット**
   - その庭園の景観上、現在どこに見えているか。
   - 表示上限に達している場合は未設定でもよい。

これにより、庭園の画面に全307属を同時表示する必要はない。

## 庭園内の控え植物
**確定**
- 庭園所属は決まっているが、現在の景観スロットに出ていない植物を「未配置」とは扱わない。
- それらは、その庭園に所属したままの**控え植栽 / 非表示植栽**として管理する。
- 編集トレイからいつでも現在の表示植物と入れ替えられる。
- 「未配置」は、開花後にまだどの庭園にも所属が決まっていない特殊状態だけに限定する。

## 幽香に任せる場合
**確定**
- `幽香に任せる` を選ぶと、解放済み庭園の中から適した所属先を幽香が決める。
- 所属先の表示枠に空きがあれば、景観上にも配置してよい。
- 表示枠が埋まっている場合でも、その庭園への所属自体は成立する。
- 既存の手動配置植物を勝手に押し出さない。
- 幽香管理の植物だけは、後により適した庭園が解放された場合に移植候補となる。

## 中央庭園
**確定**
- 中央庭園は生育適性よりも展示価値・お気に入り・ユーザーの意思を優先する特別庭園。
- 物理的に成立しない配置を除き、他庭園より環境適性の制約を緩くする。
- 中央庭園全体でも約12〜18属程度を表示目標とし、植物密度とUI視認性を優先して最終調整する。
- 中央庭園へ明示的に手動配置した植物は、幽香が勝手に別庭園へ移動させない。

## データ構造の最低要件
**確定方針**
植物ごとに最低限以下を分離して保持する。
- `assignedGardenID`
- `displayZoneID?`
- `displaySlotID?`
- `placementAuthority` (`yuuka` / `user`)
- `isDisplayPinned`
- `isFavorite`

これにより、
- 所属はしているが画面には出ていない
- 幽香管理なので後から移植可
- ユーザー固定なので勝手に動かせない
を区別する。

## 8 控え植物の景観反映

**確定方針**
- 庭園所属はしているが、現在の植栽スポットには表示されていない植物（控え植物）について、可能な庭園では**非インタラクティブな遠景・背景植栽としてごく薄く反映**してよい。
- 目的は「所属植物が増えるほど庭全体が豊かに見える」こと。
- ただし、控え植物を必ず遠景へ描写する仕様にはしない。
- **景観が壊れないことを最優先**し、庭園タイプごとに反映方法を変える。

### 庭園タイプ別の反映
**確定方針**
- 草原・日向花壇・林縁など、奥行きを見せやすい庭園:
  - 遠景・中景の小さな植生シルエットや色面として反映可能。
- 水辺:
  - 水際や対岸の補助植栽として反映可能。
- 木立・木陰:
  - 背景の葉群・下草・枝葉の密度として反映可能。
- 温室:
  - 「遠景」というより棚・奥の鉢・背景葉群として反映する。
- 中央庭園:
  - UI・幽香・主要植物の視認性を優先し、背景反映は特に控えめにする。

### インタラクション
**確定**
- 控え植物の背景反映は**タップ対象にしない**。
- 個体識別できる必要はない。
- 表示中の管理対象植物と見分けがつくよう、サイズ・彩度・コントラスト・被写界深度等で一段下げる。
- 遠景植物を選択・編集したい場合は、編集トレイから正式な表示スポットへ入れ替える。

### LOD / 描画負荷
**確定方針**
- 控え植物を307属分そのまま個別描画しない。
- 所属数や構成に応じて、背景用の簡略スプライト・クラスター・色味・葉群等へ集約する。
- 画面上の直接管理対象植物を優先し、背景植生は描画負荷・視認性に応じて省略可能。
- 端末性能や庭園構図により背景反映量を調整できるデータ駆動設計にする。

### 設計原則
**確定**
- 「控え植物が多い = 必ず遠景が植物だらけ」にはしない。
- あくまで庭の豊かさを補助する演出。
- 背景反映によって主要植物・幽香・UIの視認性が落ちる場合は、反映しない方を選ぶ。

# 13. 庭園区画の解放 / 307属属性

## 基本思想
**確定**
- 庭園区画の解放は、単なるメニュー追加ではなく、**記憶の庭園が広がったことを実感させる節目**として扱う。
- ただし解放イベントが学習・復習のテンポを妨げないよう、発生タイミングを制御する。
- 一度解放した庭園は、復習期限超過や記憶状態悪化が起きても再ロックしない。
- 学習順によって解放順が変わる分岐型とする。

## 通常の解放対象
**確定**
標準庭園候補:
- 日向花壇
- 草原
- 林縁
- 木陰
- 水辺
- 岩場
- 木立
- 温室

※ 中央庭園は初期から存在する。
※ 「曖昧の庭」は通常庭園とは別の隠し特殊区画として扱う。

## 解放判定
**確定方針 / 数値は暫定**
- 307属それぞれに持たせた庭園適性スコアを使用する。
- 各庭園について、一定以上の適性を持つ**開花済み属数**が閾値へ達した場合、その庭園を解放候補とする。
- 複数庭園に適性を持つ属は、上位候補に対して解放進行へ寄与してよい。
- 実装初期では既存の `hanazukan_habitat_design_v1.json` の適性スコア・閾値を基礎値として利用し、実機テストで調整する。

### 現在の基礎閾値案
- 日向花壇: 候補10属
- 草原: 候補10属
- 林縁: 候補7属
- 木立: 候補7属
- 温室: 候補5属
- 木陰: 候補5属
- 岩場: 候補4属
- 水辺: 候補4属

**確定**
- 最初の新区画は、総開花数が10属未満では解放しない。
- 通常の庭園解放イベント同士は、最低8属程度の新規開花間隔を空けることを初期案とする。
- 数値はハードコードせず設定データで変更可能にする。

## 複数庭園が同時に解放可能になった場合
**確定**
- 同時に複数庭園を一気に解放しない。
- 解放可能庭園を内部キューへ保持し、1つずつ節目として扱う。
- 優先順位は、概ね以下で決定する。
  1. 解放条件達成率が高い
  2. 対応植物数が多い
  3. 直近の学習内容との関連が強い
- 次の庭園は、最低解放間隔を満たした後に解放イベントを発生させる。
- キューへ入った庭園は、後から条件を下回ることがあっても候補から消さない。

## 解放イベントを発火するタイミング
**確定**
- 問題回答中・復習中・編集ドラッグ中など、ユーザー操作の途中ではイベントを割り込ませない。
- 条件達成時は内部的に `pendingUnlock` として保持する。
- 以下の**安全な節目**で解放演出を開始する。
  - 学習セッション終了後
  - 復習セッション終了後
  - ホームへ戻った直後
  - 庭園タブを開いた時
- 重要イベントが複数ある場合でも、1回の遷移で長い連続イベントを強制しない。

## 初回解放演出
**確定**
各庭園の初回解放は Level A の重要システムイベントとして扱う。

推奨フロー:
1. セッション終了 / ホーム復帰
2. イベント発生を短く示す
3. 幽香を通常より大きめに表示、または庭園側へカメラを向ける
4. 新区画の名称と特徴を簡潔に説明
5. 必要なら `見に行く` / `あとで` を選択
6. `見に行く` なら庭園タブの該当区画へ遷移
7. `あとで` ならホームへ戻し、イベントバナーまたは庭園タブに未確認マークを残す

- 初回説明は自動消去させず、ユーザー操作で進める方式を推奨する。
- 2回目以降の同種通知は短くする。

## 解放済み庭園への移植
**確定**
新区画解放時、既存植物を一律に強制移植しない。

### `placementAuthority = yuuka`
- 幽香管理の植物で、解放された庭園が現在所属先より明確に適している場合、移植候補になる。
- 所属先変更自体は幽香判断で実行してよい。
- ただし、**表示中の植物配置を一度に大量にシャッフルしない**。
- 新しい庭園の空き表示スポットへ数株だけ自然に出す、または控え植物として所属させる。
- 画面上の大きな変化がある場合は、イベントバナーや短い幽香のコメントで示す。

### `placementAuthority = user`
- ユーザーが手動配置した植物は勝手に移動しない。
- より適した新区画ができても、「移植候補」として提案するだけ。
- 提案を無視してもペナルティなし。

## 「幽香に任せる」の意味
**確定**
- `幽香に任せる` は、単なる自動配置アルゴリズムではなく、**配置判断と将来の移植判断を幽香へ委任する選択**。
- 幽香は適性だけでなく、以下を総合して判断してよい。
  - 庭園適性
  - 表示枠の空き
  - 植物サイズ
  - 景観バランス
  - 同属 / 同タイプの偏り
  - ユーザーのお気に入り状態
- 幽香に任せた結果は、必ずしも数値上の最適値一点へ機械的に集約しない。
- 多少の景観的な好み・偏りを許容し、「幽香が決めた」感覚を残す。

## ロック中庭園の見せ方
**確定方針**
- 通常庭園は、庭園タブ内でロック中であることを表示してよい。
- ただし**正確な解放数値を常時見せない**。
- 例:
  - `水辺を好む植物が増えると……`
  - `木陰に似合う植物が集まり始めている`
- 進捗を見せる場合も、数値カウンターより曖昧な段階表示を優先する。
- これにより「あと2属稼ぐ」だけの作業感を減らす。
- 「曖昧の庭」は隠し区画のため、解放前は名称・条件を表示しない。

## 解放後の未確認状態
**確定**
- 解放イベントで `あとで` を選んだ場合、庭園タブの該当区画に控えめな未確認マークを出す。
- ホームへ恒常的な大きな通知を置かない。
- イベントバナーに短期間表示してもよい。
- 一度区画を訪れたら未確認状態を解除する。

## 解放が長期間起きない場合
**確定方針**
- 学習順によって特定庭園が長く開かないこと自体は許容する。
- ただし、庭園拡張が極端に停滞してゲーム体験が単調になる場合は、実機・プレイログを見て閾値を調整する。
- 「一定日数経過だけで強制解放」のような救済は初期実装では入れない。
- 必要なら将来、幽香から特定環境の植物を学ぶヒントを出す程度に留める。

## 解放イベント履歴
**確定**
- 庭園解放は「最近の出来事」に記録する。
- 初回イベントを見逃した / `あとで` を選んだ場合でも後から概要を確認できる。
- 通常の幽香雑談ログにはしない。

# 14. 曖昧の庭

## 位置づけ
**確定**
- 「曖昧の庭」は通常の生態庭園とは別枠の**隠し特殊庭園**。
- 復習遅れ・記憶低下が一定以上たまった時に初めて存在が明らかになる。
- 本来の庭園に定植されている植物は移動しない。
- 曖昧の庭に現れるのは、記憶が薄れた植物の**「似姿」**のみ。
- 似姿は実体ではなく、記憶状態を視覚化するための表示。
- 一度解放された後は常設し、条件を満たさなくなっても再ロックしない。

## 初回解放条件
**暫定**
以下のどちらかを初めて満たした時に解放候補とする。
- 「忘却寸前」以上の状態が5属同時
- または「忘却」状態が3属同時

- 条件値は実機・復習負荷を見て調整可能な設定値にする。
- 解放前は庭園一覧に名称・条件を表示しない。
- 単なるロック表示にもせず、存在自体を伏せる。

## 初回解放イベント
**確定**
- Level A の重要システムイベントとして扱う。
- 復習・学習・編集の途中には割り込ませず、安全な節目で発火する。
- 初回は幽香が専用案内を行ってよい。
- 「見に行く / あとで」を選べる。
- `あとで` を選んでも、庭園タブまたはイベント履歴から後で訪問できる。
- 初回のみ丁寧に案内し、2回目以降は通常庭園として扱う。

## ビジュアル方針
**確定**
- 通常庭園より彩度を落とす。
- 薄い霧、低コントラスト、静かな光、ややぼやけた奥行き等を使ってよい。
- 魔法陣、強い発光、粒子エフェクト、派手な幻想演出は使わない。
- 「別世界」ではなく、**同じ記憶の庭園なのに輪郭と色だけが失われている**ように見せる。
- 音を実装する場合は、通常庭園より環境音を少なくし、静けさを感じる方向。
- 幽香は通常通り存在してよいが、通常庭園より落ち着いた行動・発話頻度にする。

## 似姿の表示
**確定**
- 似姿は記憶状態が悪い植物から優先して表示する。
- 表示優先順位は概ね:
  1. 忘却
  2. 忘却寸前
  3. 期限超過が長い
  4. 直近の正式復習で失敗が続いている
- 似姿の見た目は、本来の植物モデルを基礎に:
  - 彩度低下
  - セピア〜モノクロ化
  - わずかな透明化
  - 輪郭の弱まり
  を状態に応じて使う。
- 似姿自体を不気味・枯死表現へ寄せすぎない。
- 「忘れた = 植物が死ぬ」という罰表現にはしない。

## 表示上限
**確定方針 / 数値は暫定**
- 曖昧の庭に多数の対象が存在しても、全てを一画面へ直接描画しない。
- 直接選択できる似姿は、通常庭園と同様におおむね12〜18属程度を目安とする。
- 標準目標は約15属。
- それ以上ある場合は、最も状態の悪いものを優先表示する。
- 残りは背景の淡いシルエット・植生密度・「他にも曖昧な記憶がある」ことを示す補助表現へ集約してよい。
- `手入れ` 画面では全対象を一覧確認できるため、曖昧の庭だけで全件管理できる必要はない。

## 植物選択と復習
**確定**
- 似姿をタップすると、その植物を選択できる。
- 復習期限に達している植物のため、選択直後に答えとなる科名・属名・和名を自動表示しない。
- 下部アクションは概ね:
  - `思い出す / 復習する`
  - `図鑑を見る`
  - `閉じる`
- 正式復習へ入った場合は通常の復習ロジックを使用する。
- `図鑑を見る` では復習保護中の図鑑詳細へ移動する。ページを開くだけでは `relearnedAt` は付かない。
- `幽香に訊く` 等で主要暗記情報を明示的に確認した場合のみ `relearnedAt` を記録する。
- 似姿や植物モデルを眺めただけでは再学習扱いにしない。

## 復習後の変化
**確定**
- 正式復習結果が確定し、次回正式復習期限が再設定された時点で、その植物の現在の超過状態は解消する。
- そのため本来の庭園にいる植物は正常側の色彩・輪郭へ戻る。
- 正解 / 惜しい / 不正解によって次回間隔は異なるが、いずれも「今回の手入れを行った」ことは庭上の見た目へ反映する。
- 曖昧の庭の似姿は、対象植物が表示条件を外れた時点で消える。
- 消失演出は控えめにする。
  - 色が少し戻る
  - 輪郭が明瞭になる
  - その後、画面切替または短いフェードで姿がなくなる
- 派手な浄化・発光・粒子演出は使用しない。

## 空になった曖昧の庭
**確定**
- 解放後、対象植物が0属になっても庭自体は残る。
- 似姿のない、静かな庭として表示する。
- 「全て解消したから閉鎖 / 再ロック」はしない。
- 空の状態は、復習が行き届いていることを穏やかに感じられる演出として扱う。
- 大げさな報酬画面や勝利演出は必須ではない。

## 配置編集
**確定**
- 曖昧の庭では植物配置編集を行わない。
- 似姿は記憶状態に応じて自動配置される。
- 本来の植物の定植先・表示位置には一切影響しない。
- `植栽編集` ボタンは表示しない。

## アクセス導線
**確定方針**
- 解放後は `庭園` タブ内の「特殊庭園」扱いとしてアクセス可能にする。
- ホーム画面に常時大きな専用ボタンを追加しない。
- 復習対象が多い時は `手入れ` 側から「曖昧の庭を見る」導線を出してよい。
- 初回解放後、イベントバナーから短期間誘導してもよい。

## 設計思想
**確定**
- 曖昧の庭は「罰の庭」ではない。
- 復習負債を責めるためではなく、**記憶が薄れているものを可視化し、思い出すきっかけを作る場所**。
- ユーザーに不安や義務感を過剰に与えず、静かな違和感と「手入れしたい」気持ちを生む方向を目指す。

# 15. 記憶状態 / 正式復習アルゴリズム

## 基本間隔
**確定**
正式復習の基準間隔は以下。
- 1日
- 3日
- 7日
- 14日
- 30日
- 60日
- 120日

各植物・各復習状態は、現在の段階と次回期限を保持する。

## 正解
**確定**
- 直近約24時間に `relearnedAt` がない通常の正式復習で正解した場合、原則として**1段階進む**。
- 例:
  - 7日段階 → 14日段階
  - 30日段階 → 60日段階
- 120日段階で正解した場合は120日を維持する。
- 次回期限は原則として回答時点から次段階の基準間隔後。

## 「惜しい」
**暫定**
- 1文字違い等、「知識自体はほぼ想起できている」と判定した回答。
- 段階は進めない。
- 段階も下げない。
- **現在と同じ基準間隔でもう一度**正式復習する。
- 例: 30日段階で惜しい → 30日段階のまま、次回期限を回答時点から30日後。
- 実機・学習ログで「甘すぎる」と判明した場合のみ再調整する。

## 不正解
**暫定**
- 不正解時は1段階下げる。
- ただし次回復習を単純に下段階の満額間隔へせず、**失敗した段階の1つ前と2つ前の基準間隔の平均**を回復用間隔として使う。
- これにより、完全な初期化は避けつつ、通常より早く再確認する。

例:
- 120日段階で不正解 → 段階は60日へ。次回は `(60 + 30) / 2 = 45日` 後。
- 60日段階で不正解 → 段階は30日へ。次回は `(30 + 14) / 2 = 22日` 後。
- 30日段階で不正解 → 段階は14日へ。次回は `(14 + 7) / 2 = 10.5日` 後（実装上の丸めは設定）。
- 14日段階で不正解 → 段階は7日へ。次回は `(7 + 3) / 2 = 5日` 後。
- 7日段階で不正解 → 段階は3日へ。次回は `(3 + 1) / 2 = 2日` 後。
- 3日・1日段階で不正解 → 最短1日を基準とする。

**設計意図**
- 1回の失敗で記憶進行を大幅に初期化しない。
- ただし「忘れていた」ことは次回間隔へ反映する。
- 回復用間隔で正解すれば、通常ルールにより再び上位段階へ戻れる。

## 期限より早い自主復習
**暫定**
- 期限前に自由復習して正解しても、正式な段階アップは行わない。
- ただし、各段階につき**1回だけ**小さな延命ボーナスを与える。
- 初期案:
  - `現在の残り時間 × 10%` を次回期限へ加算。
  - 同じ段階で2回目以降の早期復習は、記録はするが追加延命なし。
- 延命ボーナスは直近24時間に `relearnedAt` がない自力正解時のみ有効。
- 期限超過後は「早期復習」扱いにしない。
- 段階が変わった時点で、その段階用の早期延命権を1回分リセットする。

### 期限前の自由復習で正解以外だった場合
**確定**
- 期限前の自由復習で `惜しい` の場合:
  - 段階は維持する。
  - **元の次回期限を延長しない**。元の `nextReviewAt` を維持する。
- 期限前の自由復習で `不正解` の場合:
  - 既定の1段階ダウンは適用する。
  - ただし、自由復習したことで本来の期限より後ろへ延期されることがないよう、
    `nextReviewAt = min(元のnextReviewAt, now + 回復用間隔)` とする。
- 目的は「早く確認したことで、惜しい / 不正解なのに復習日が遠のく」逆転現象を防ぐこと。

**設計意図**
- やる気がある時の自主復習を完全に無意味にしない。
- 一方、早期復習の連打だけで120日等へ進めない。
- 10%値は実機テストで調整可能な設定値とする。

## 期限超過
**確定方針**
- 期限超過によって「未消化タスク」を日数分積み増さない。
- 1植物につき復習待ちは常に1件として扱う。
- 期限超過の主なペナルティは:
  - `overdueSeverity` の上昇
  - 庭モデルの退色
  - 曖昧の庭への出現
  - おまかせ復習での優先度上昇
- 「3日遅れたので3回復習が必要」のような負債増殖は行わない。

## 復習量の上限思想
**確定**
- おまかせ復習は原則最大5属程度。
- 大量に期限超過していても、1日の必須感を過剰に増やさない。
- 5属終了後に続けたいユーザーだけ、任意で追加復習できる。
- 長期離脱から戻ったユーザーへ大量の未消化タスクを一度に突きつけない。
- 継続利用を優先し、「返済不能な復習負債」を作らない。

## 調整可能な数値
**確定方針**
以下はロジックを変えずに実機調整できる設定値として持つ。
- 早期自主復習の延命率（初期10%）
- 再学習直後の保護時間（初期24時間）
- 写真問題ボーナス（初期+5%）
- 復習保護開始時間
- `decayWindow` の係数・上下限
- 5段階表示の境界値
- おまかせ復習の最大件数（初期5属）

## 答えを見た直後の扱い（内部的な再学習状態）
**確定**
- 復習保護期間中に主要暗記情報を確認した場合は、属単位で `relearnedAt` を記録する。
- 3つの問題形式は互いに情報が連動するため、保護期間中は形式別ではなく**その属全体を再学習直後**として扱う。

`relearnedAt` から約24時間以内:
- 正式復習の段階アップ: なし
- 次回期限の本格延長: なし
- 期限のリセット: なし
- 庭上の退色 / `overdueSeverity` の巻き戻し: なし
- おまかせ復習の自動選出: 原則除外
- 自由復習: 可能だが、記録上の練習扱い

約24時間経過後:
- 通常の正式復習効果へ戻る。

再学習状態の主な発生源:
- 復習保護中の図鑑で `幽香に訊く`
- 復習保護中の演習で正答を見る
- 今日の手入れ開始前プレビュー等から、正式復習を行わず答えを確認する

**補足**
- 通常の正式復習で `惜しい / 不正解` となり正答を確認した場合は、その正式復習結果に従って次回期限を設定する。
- そのケースへ追加の24時間ロックを重ねない。

**設計意図**
- 答えを見た直後の正解で復習段階を進めない。
- 答えを見た直後だけ別の回復ゲージを設けず、庭上の見た目は次回期限と超過時間を中心に一貫して決める。

## 図鑑閲覧と記憶状態
**確定**
- 庭上の見た目は「期限までの残り時間で徐々に悪化する」方式にしない。
- 図鑑閲覧だけで庭上の状態を直接回復する仕様は**非採用**とする。
- 図鑑閲覧は学習・再学習として有益だが、次回正式復習期限や庭上の劣化進行を直接巻き戻さない。
- 復習保護期間中に主要暗記情報を見た場合は、既定の `relearnedAt` ルールを適用する。
- 復習保護期間より前の通常図鑑閲覧は、自由な自主学習として扱う。
- これにより「図鑑を繰り返し見て景観劣化へ対抗する」抜け道を作らない。

## 写真問題ボーナス
**暫定**
- 写真登録済みの属では、正式復習後に任意の写真問題をボーナス問題として出せる。
- 写真問題に正解した場合、通常の段階進行に加えて、**新しく設定された次回間隔を5%延長**する。
- 例:
  - 30日間隔へ進んだ後に写真問題正解 → 31.5日相当
  - 120日間隔 → 126日相当
- 延長は1回の正式復習につき1回まで。
- 写真問題で不正解でも、通常復習結果へ追加ペナルティは与えない。
- 5%は設定値とし、実機で「存在感が薄すぎる / 強すぎる」を見て調整する。
- 演習として解いた写真問題は、この正式復習ボーナスを発生させない。

## 記憶状態の5段階表示 / 庭上の劣化
**確定方針**
- 庭上の植物は、**正式復習期限までは原則として正常な色彩を保つ**。
- 期限前から徐々に色が悪くなる表現は行わない。
- 復習期限当日も基本的には通常色のまま。
- 期限到達〜ごく軽い超過では、必要なら色彩低下ではなく、ごく軽い「記憶の揺らぎ」を示す。
  - わずかなぼやけ
  - ごく短いノイズ / 輪郭の揺れ
  - 微細なコントラスト低下
- **本格的な退色は期限超過後に進行する。**

ユーザー向け表示は当面5段階とする。
1. **安定**
   - 期限前。
   - 見た目は通常。
2. **手入れどき**
   - 期限到達〜軽度超過。
   - 色はほぼ正常。必要なら軽い揺らぎだけ。
3. **乾き始め**
   - 超過が進んだ状態。
   - 軽い彩度低下。
4. **色褪せ**
   - さらに超過した状態。
   - 明確な彩度低下〜セピア寄り。
5. **かなり曖昧**
   - 大幅超過。
   - モノクロ寄り、輪郭弱化、必要なら軽い透明化。

- 内部では連続的な `overdueSeverity` を持ち、UIでは5段階へ丸める。
- 「忘却寸前 / 忘却」は5段階目の内部閾値として扱い、曖昧の庭の解放判定等に利用する。

## 超過進行の内部計算
**暫定**
- 見た目の悪化は「単純な超過日数」だけではなく、現在の復習間隔も考慮する。
- 理由:
  - 1日段階で2日遅れた場合と、120日段階で2日遅れた場合を同じ重さにすると不自然なため。
- 初期案:
  - `scheduledInterval = nextReviewAt - lastFormalReviewAt`（その周期に実際に設定された間隔。回復用間隔・写真ボーナス等を反映）
  - `decayWindow = clamp(scheduledInterval × 0.5, 2日, 30日)`
  - `overdueSeverity = overdueTime / decayWindow`
- 例:
  - 1日段階 → 約2日超過で重度
  - 7日段階 → 約3.5日超過で重度
  - 30日段階 → 約15日超過で重度
  - 60日以上 → 最大約30日超過で重度

初期の視覚境界案:
- `overdueSeverity <= 0` : 安定
- `0 < severity < 0.2` : 手入れどき（色彩正常、軽い揺らぎのみ）
- `0.2 <= severity < 0.45` : 乾き始め
- `0.45 <= severity < 0.75` : 色褪せ
- `severity >= 0.75` : かなり曖昧
- `severity >= 1.0` : 内部的な「忘却」候補

- 数値はすべて設定データとして調整可能にする。
- 目的は罰を強めることではなく、「期限を守れている間は庭を美しく保ち、超過が長いほど静かに色を失う」こと。


## おまかせ復習の優先順位
**確定**
- おまかせ復習は**次回期限が早い順**に選ぶ。
- 期限超過しているものは、期限日時が古いものから優先される。
- その後、期限が近い未超過のものを選ぶ。
- 対象は原則最大5属。
- 「期限が近い」の対象範囲には閾値を設け、まだ十分先の植物しかない場合は `今日は特に必要なし` とする。
- 同一属で複数形式候補がある場合は、その回では原則1形式だけ選ぶ。
- 形式選択は、苦手度・前回出題からの経過・ローテーションを考慮する。

# 16. 手入れ画面 / 正式復習ハブ

## 役割
**確定**
- 下部タブの `手入れ` は、開花済み植物の正式復習と記憶状態確認をまとめるハブ画面。
- 「復習をたくさん消化する作業画面」ではなく、**今日必要な手入れ量を分かりやすく示す画面**とする。
- ホーム画面には復習用の大きな常設ボタンを置かず、正式復習の主導線はこのタブへ集約する。

## 画面構成
**確定方針**
上から以下の順を基本とする。

### A. 今日の状態
- 画面上部に簡潔な要約を表示。
- 表示候補:
  - `今日の手入れ`
  - おまかせ復習対象数
  - 期限超過中の属数
  - 再学習直後で今日は本番復習を勧めない属数
- 数値を「借金」「未消化」等の強い言葉で表現しない。

### B. 今日の手入れ（主ボタン）
- 画面上で最も大きい行動。
- おまかせ復習を開始する。
- 最大5属。
- 期限超過・期限間近の順で自動選出。
- 対象がない場合は `今日は特に手入れの必要はありません` と表示し、主ボタンは非活性または `自由に見直す` へ置換してよい。

### C. 自由復習
- 好きな属を選んで正式復習できる。
- 期限前の属も選択可能。
- 期限前正解では段階アップせず、既定の早期復習ボーナスのみ適用。
- `relearnedAt` から24時間以内の属を選んだ場合は、弱体化中であることを短く表示する。

### D. 曖昧の庭
- 解放済みの場合のみ表示。
- 復習状態が悪化している植物がある時は、控えめに件数を表示してよい。
- `曖昧の庭を見る` から特殊庭園へ移動。
- 未解放時は項目そのものを表示しない。

### E. 記録・履歴
- 現行 `記録` タブにある情報は、手入れ画面内の副次セクションまたはサブ画面へ再配置する。
- 表示候補:
  - 正式復習履歴
  - 演習履歴
  - 形式別正答率
  - 開花数
  - 写真登録数
  - 最近の出来事
- `手入れ` の主目的は復習なので、統計カードを上部へ大量に並べない。

## おまかせ復習の表示
**確定**
- 主ボタンには、実際に今日出す予定の属数だけを表示する。
  - 例: `今日の手入れ　5属`
- 期限超過中の総数が5属を超えていても、主ボタンを `12件残っています` のような圧の強い表示にはしない。
- 必要なら小さく `ほかにも手入れ待ちがあります` とだけ表示する。
- 5属終了後に:
  - `今日はここまで`
  - `もう少し続ける`
  を選べる。
- 追加復習も1回5属程度の小さな単位で続ける。

## 復習対象一覧
**確定方針**
- 手入れ画面から `手入れ待ちを見る` を開き、対象植物を一覧確認できる。
- 並び順:
  1. 期限超過が長い
  2. 期限が近い
- 一覧には最低限:
  - 属名
  - 記憶状態
  - 期限 / 超過目安
  - 所属庭園
- 詳細な正答情報は復習前に見せすぎない。
- 一覧から個別に正式復習へ入れる。

## 再学習直後の表示
**確定**
- `幽香に訊く`、復習保護中の演習等で `relearnedAt` が付いた属は、約24時間おまかせ復習から外す。
- 手入れ画面では必要に応じて:
  - `今日は確認したばかり`
  - `明日以降に思い出してみる`
  等の穏やかな状態表示を使う。
- 「復習不可」「失敗」等のネガティブ表示は使わない。
- 自由復習なら選択可能。

## 自由復習の選択UI
**確定方針**
- 図鑑と同じ307属一覧をそのまま複製せず、復習向けの絞り込みを優先する。
- フィルター候補:
  - 期限超過
  - 期限が近い
  - お気に入り
  - 庭園別
  - 科別
  - 最近間違えた
- 検索も利用可能。
- 1属選択でそのまま正式復習。
- 複数選択して小さな復習セットを作る方式は将来拡張として許容する。

## 復習結果画面
**確定**
- 1回のおまかせ復習（最大5属）終了後に簡潔な結果を表示する。
- 表示候補:
  - 正解 / 惜しい / 不正解
  - 次回手入れ予定
  - 色が戻った植物
  - 写真問題ボーナスが付いた場合の延長
- 大げさなスコア・ランク・評価は使わない。
- `庭へ戻る`
- `もう少し続ける`
を主な終了導線とする。

## ホームとの関係
**確定**
- ホームでは `手入れ` タブに控えめな通知バッジを出してよい。
- バッジは「今日の手入れ対象がある」ことだけを示し、件数を強く主張しない設計を優先する。
- 退色植物をゾーン観察した場合は、その植物から直接正式復習へ入れる。
- ホームに「今日の復習を消化しろ」と感じる大型警告は出さない。

## 設計思想
**確定**
- 復習圧は存在するが、復習負債を心理的に膨らませない。
- ユーザーがアプリを再開した時に、まず大量の未処理件数を突きつけない。
- 「今日は5属だけ手入れする」で区切れることを重視する。
- 長期的には庭の景観が復習の動機になり、手入れ画面はその行動を支える役割に留める。

## 10 今日の手入れ開始前プレビュー

### 基本方針
**確定**
- `今日の手入れ` を開始する前に、今回対象となる最大5属を**視覚的にプレビュー**できる。
- ただし復習保護中のため、科名・ラテン語属名・属和名などの主要暗記情報は表示しない。
- 表示してよいもの:
  - 植物モデル / 写真サムネイル
  - 所属庭園
  - 記憶状態
  - 「手入れどき」「超過中」等の状態
- 目的は答えを教えることではなく、「今日はこの植物たちを思い出す」心構えを作ること。

### 視覚ヒントの扱い
**確定方針**
- 植物の形・花・葉などが見えることは、正式復習前の**弱い視覚ヒント**として許容する。
- これはカンニングではなく、負荷を下げて継続しやすくするための設計。
- 主要暗記情報の文字列は伏せる。
- 将来、より厳密な想起を好むユーザー向けに `プレビューを簡略化` / `ヒントなし` 設定を追加してよい。

### 「思い出せない」時のリカバリ
**確定**
- 開始前プレビューで「これはもう分からない」と感じた植物について、**間違えるまで待つ必要はない**。
- その植物から `幽香に訊く` / `思い出し直す` を選べる。
- 選択した場合:
  1. 主要暗記情報を表示する。
  2. その属に `relearnedAt` を記録する。
  3. その属は今日のおまかせ復習セットから外す。
  4. 可能なら次順位の手入れ候補を1属補充する。
  5. その植物は約24時間後以降に正式復習候補へ戻す。
- 答えを見ただけでは期限・段階・退色状態を回復しない。
- したがって、難しい植物を繰り返し先送りして庭の状態だけ維持することはできない。

### 開始前プレビューでの操作
**確定方針**
- 基本操作:
  - `この5属を手入れする`
  - 各植物の `幽香に訊く`
  - `戻る`
- 対象5属をユーザーが自由に並び替える必要はない。
- 正式復習の問題形式は、復習開始後に決定する。

## 11 近日の手入れ予告

### 目的
**確定方針**
- 「気付いた時には復習保護に入っていて図鑑情報が伏せられていた」を減らすため、手入れ画面に**近日の手入れ**を置く。
- これは義務タスク一覧ではなく、「この辺がそろそろ来る」という予告。

### 表示範囲
**暫定**
- 2〜3日程度先までの正式復習予定を表示候補とする。
- ただし1日段階など、そもそも予告期間より短い復習間隔では無理に先行表示しない。
- 表示件数は少なめに抑え、長い予定表にはしない。

### 保護前 / 保護中の表示
**確定**
- 復習保護開始より前:
  - 通常の図鑑情報へアクセスできる。
  - ここで見直すことは自由な自主学習として扱う。
- 復習保護開始後:
  - 主要暗記情報は伏せる。
  - 植物モデル / 写真 / 庭園所属 / 状態等の非答え情報だけ表示。
  - 必要なら `幽香に訊く` で再学習できる。

### 設計意図
**確定**
- ユーザーに「突然テストが来た」と感じさせない。
- ただし、事前に答えを全部並べて正式復習を形骸化させない。
- 早めに気付いて自主学習する自由と、直前は答えを伏せるルールを両立する。

# 17. 図鑑 / 情報隠し / 復習保護

## 図鑑の役割
**確定**
- 図鑑は307属すべてを最初から閲覧できる、制限のない参照機能とする。
- 未着手・育苗中・開花済み・記憶低下中のいずれであっても、図鑑自体をロックしない。
- 図鑑は「答えを見ると罰を受ける場所」ではなく、**植物を知る・学び直すための正規の入口**。
- ただし、復習保護期間中に主要暗記情報を明示的に見た場合は、既定の `relearnedAt` ルールを適用する。
- 図鑑を開く自由と、時間を空けた自力想起の価値を両立する。

## 図鑑一覧
**確定方針**
- 307属一覧を検索・スクロールできる。
- 検索対象:
  - ラテン語属名
  - 属和名
  - 科名
  - 旧科名
  - 必要に応じて備考・代表種
- 既存実装の検索ロジック・307属データは再利用候補。
- 一覧は図鑑へのナビゲーションを主目的とし、1セルへ情報を詰め込みすぎない。
- 植物サムネイル / 簡略イラストを表示できる場合は使用してよい。
- 一覧の視認性を優先し、低コントラストな文字や過剰なカード装飾は避ける。

### 一覧閲覧の扱い
**確定**
- 一覧・検索結果をスクロールしてセルが画面に見えただけでは `relearnedAt` を発生させない。
- 理由:
  - 偶然視界に入った情報まで厳密に追跡すると、図鑑の閲覧性を損なうため。
  - 再学習状態は「意図して答えを参照した」操作を中心に記録する。
- `relearnedAt` は、復習保護中に**幽香に訊く / 演習や正答表示で答えを確認する**等の明確な参照操作で発生させる。
- これは不正防止システムではなく、復習効果を自然に評価するための近似ルールとする。

## 一覧の絞り込み / 並び替え
**確定方針**
初期実装で最低限以下を扱える構造にする。
- 科別
- 未着手 / 育苗中 / 開花済み
- 写真あり / なし
- お気に入り
- 記憶状態
- 庭園所属
- 復習待ち

**暫定**
- UIは検索欄＋フィルターボタン程度に留め、常時大量の絞り込みチップを並べない。
- 並び順候補:
  - ラテン語順
  - 和名順
  - 科名順
  - 最近見た
  - 最近開花
- 最終的な初期表示順は実機で調整する。

## 図鑑詳細ページ
**確定**
詳細ページには、少なくとも以下の情報を持つ。
- ラテン語属名
- 読み
- 属和名
- 科名
- 旧科名（存在する場合）
- 備考 / 特徴
- 写真 / 観察記録
- 外観バリエーション
- 必須3形式の開花進捗
- 開花済みの場合:
  - 記憶状態
  - 次回手入れ目安
  - 現在の庭園所属
- お気に入り状態

**設計原則**
- 1画面へ全情報を密集させず、縦スクロールで自然に読む。
- 図鑑詳細はスクロール画面でよい。ホームの固定画面ルールは適用しない。
- 詳細な学習履歴・正答率はサブセクションや別画面へ逃がしてよい。

## 図鑑詳細からの行動
**確定**
植物状態に応じて以下を出せる。

### 未着手 / 育苗中
- `咲かせる`
  - この属を選択済みの状態で新規学習へ。
- `演習する`
  - 任意練習へ。
- `写真を追加`

### 開花済み
- `演習する`
- 復習期限に近い / 超過している場合は `手入れする`
- `庭で見る`
  - 現在所属庭園・表示ゾーンへ遷移できる場合に表示。
- `写真を追加`
- `外観を変更`（バリエーション解放済みの場合）

- 詳細ページを「学習・復習・庭」へのハブとして使えるが、主情報の閲覧を妨げないようアクション数を整理する。

## 図鑑詳細を開いた時の扱い
**確定**
- 通常時は、図鑑詳細を普通に閲覧できる。
- 復習保護期間中は、主要暗記情報を一律に伏せるため、**詳細ページを開いただけでは `relearnedAt` を発生させない**。
- 写真・観察記録・庭園所属・外観バリエーション等は通常通り閲覧可能。
- 伏せた主要暗記情報を `幽香に訊く` で開いた時点で、その属を再学習直後として扱う。
- 図鑑タブ自体は常に参照可能であり、「先に復習しなければ閲覧できない」仕様にはしない。

## 情報隠しモードの目的
**確定**
- 図鑑をそのまま単語帳のように利用するための閲覧補助モード。
- 正式復習とは別。
- 「どの情報を隠すか」をユーザーが選び、自分で思い出してから答えを開ける。
- 図鑑のどこからでも開始できる。

## 隠せる情報
**確定方針**
最低限以下を個別にON/OFFできる。
- 科名
- ラテン語属名
- 属和名
- 旧科名
- 備考 / 特徴
- 代表種等、将来追加される暗記対象情報

**確定**
- 写真・庭園所属・記憶状態等、暗記対象ではない情報は初期状態では隠す必要はない。
- 複数項目を同時に隠せる。

## 隠し設定のプリセット
**暫定**
手動チェックに加え、問題形式に対応するプリセットを用意してよい。
例:
- `属 → 科`
  - 属名を表示し、科名を隠す。
- `和名 → Latin`
  - 属和名を表示し、ラテン語属名を隠す。
- `Latin → 和名`
  - ラテン語属名を表示し、属和名を隠す。
- `全部隠す`
  - 暗記対象項目をまとめて隠す。

- プリセットはショートカットであり、個別設定を制限しない。

## 隠し表示の見た目
**確定方針**
- 隠した項目は、庭と調和するマットな紙片・伏せ札・ブラインド等の表現を使う。
- 黒い塗りつぶしや派手な発光カードにはしない。
- 隠している項目が何の種類かは分かってよい。
  - 例: `科名　［タップして表示］`
- 答えそのものの文字幅・文字数が推測できる表示は避ける。

## 答えを開く操作
**確定**
- 隠した情報をタップすると、そのページ上で答えを表示する。
- 復習保護期間中に主要暗記情報を開いた場合は、その属に `relearnedAt` を記録する。
- 保護期間外の情報隠しモードは自主学習として扱い、正式復習まで24時間以上空けば通常の復習効果を妨げない。
- 次の属へ移動した場合、隠した項目は再び隠れた状態から開始する。

**暫定**
- 長押し中だけ一時表示し、指を離すと再び隠す操作は将来追加可能。
- v1では単純なタップ開閉だけでよい。

## 情報隠しモード中の連続閲覧
**確定方針**
- 現在の検索結果 / フィルター結果の範囲で `前へ / 次へ` を使い、属を連続して見られるようにする。
- ページを切り替えても「何を隠すか」の設定は維持する。
- 答えを開いた状態は属ごとにリセットし、次の属では再び伏せる。
- これにより、図鑑を単語帳的に連続利用できる。

## 情報隠しモードと正式復習の違い
**確定**
- 情報隠しモード:
  - 自主学習 / 再学習。
  - 回数自由。
  - 復習保護期間中に答えを開けば `relearnedAt`。
  - 正式復習段階は進めない。
- 正式復習:
  - 期限・`relearnedAt`・回答結果を考慮。
  - 時間を空けた自力想起を評価。
  - 正解時に段階アップ・次回期限更新を行う。

- 両者を見た目・文言の両方で区別し、「情報を隠したから正式復習扱い」にはしない。

## 図鑑のビジュアル方針
**確定方針**
- 植物標本帳・園芸図鑑・観察ノートの要素を取り入れる。
- 庭画面より情報密度は高くてよいが、同じアプリのデザイン言語を維持する。
- 背景:
  - 生成り
  - 落ち着いた紙色
  - くすんだ緑
  等を基調候補とする。
- 区切り:
  - 細線
  - 紙面余白
  - 小さな植物モチーフ
  を利用し、カードを過剰に積み重ねない。
- 強い金属枠・過剰なグラデーション・ファンタジー装飾は使わない。
- 文字の可読性は庭との調和より優先し、背景との十分なコントラストを必ず確保する。

## 現行実装からの再利用
**確定**
積極的に再利用する候補:
- 307属データ
- 検索
- 属詳細情報
- 3形式の進捗
- 写真データ
- 情報隠し機能のロジック
- 学習履歴 / 正答率データ

作り直す:
- 暗色カード中心の最終ビジュアル
- 旧来の形式別答え閲覧管理（新仕様では属単位の `relearnedAt` と復習保護へ置換）
- 図鑑と庭で統一されていないデザイン言語

## 16 復習保護（復習直前の図鑑表示）

### 基本思想
**確定**
- 図鑑は普段は普通に閲覧できる。
- ただし正式復習が近づいた植物だけ、**主要な暗記情報をまとめて伏せる**。
- 目的は「図鑑を使えなくする」ことではなく、正式復習直前のうっかり答え閲覧を防ぐこと。
- どの問題形式が次に出るかは、復習開始前には決定しない。
- 伏せる項目を形式ごとに変えず、主要暗記情報を一律に伏せることで出題形式の事前推測も防ぐ。

### 復習保護期間
**暫定**
- ユーザー向けには「復習が近づくと記憶が不安定になり、図鑑の暗記情報が伏せられる」と説明する。
- 内部の初期設定は以下を候補とする。
  - 保護開始 = `min(24時間, 現在の復習間隔の1/3)` 前
- 例:
  - 1日段階 → 約8時間前から保護
  - 3日段階以上 → 原則24時間前から保護
- 理由:
  - 1日段階で丸24時間伏せると、開花直後から図鑑がほぼ常時保護状態になってしまうため。
- 時間幅は設定値として調整可能にする。
- 暦日ではなく実経過時間で判定する。

### 復習保護中に伏せる情報
**確定**
主要暗記対象をまとめて伏せる。
- 科名
- ラテン語属名
- 属和名
- 旧科名や代表種等、将来正式問題へ使う情報

通常表示してよいもの:
- 写真
- 観察記録
- 庭園所属
- 外観バリエーション
- 記憶状態
- 次回手入れ目安
- その他、正式問題の答えへ直接ならない情報

- 図鑑詳細を開いただけでは復習効果を弱めない。

### 「幽香に訊く」
**確定方針**
- 保護中でも、ユーザーは伏せた暗記情報をいつでも確認できる。
- UI上は `幽香に訊く` 等、世界観に合う入口を使う。
- 入口を押すと、伏せていた主要暗記情報をまとめて表示する。
- 長い警告ダイアログは挟まない。
- 表示後は、その属を「再学習直後」として扱う。

### 再学習直後の扱い
**確定**
- 保護中に `幽香に訊く`、演習、正答表示等で答え関係を確認した場合、その属に `relearnedAt` を記録する。
- 問題形式ごとの細かな閲覧管理より、**属全体を再学習直後として扱う**。
- 理由:
  - 3つの問題形式は互いに答えを推測できる関係にあり、1形式だけ見ても残りへ影響するため。
  - ユーザー向けルールを単純化するため。

`relearnedAt` から約24時間以内:
- 正式復習で正解しても段階アップなし。
- 次回期限の本格延長なし。
- 期限のリセットなし。
- 庭上の退色 / `overdueSeverity` の巻き戻しなし。
- 回答履歴は残す。

約24時間経過後:
- 通常の正式復習効果へ戻る。

### おまかせ復習との連携
**確定**
- `relearnedAt` から24時間以内の植物は、原則として**おまかせ復習の自動選出から外す**。
- 「再学習したばかりなので、明日以降に思い出してみる」状態として扱う。
- ユーザーが自由復習で明示的に選んだ場合は回答可能だが、既定の弱体化効果になる。
- これにより、アプリ側が低効果な復習を自動で勧めることを避ける。

### 保護期間より前に図鑑を見た場合
**確定**
- 保護期間より前は通常の図鑑として閲覧できる。
- その閲覧は普通の学習・自主復習として肯定する。
- 次回期限自体は動かさない。
- 庭上の退色状態も直接巻き戻さない。
- 正式復習まで24時間以上空けば、通常効果の正式復習を受けられる。
- 例:
  - 復習2日前に図鑑で確認
  - 翌日以降、十分時間が空いて正式復習
  - 通常の想起判定として扱う

### 拡大観察モード
**確定**
- 復習保護中の植物を拡大観察した場合、主要暗記情報は自動表示しない。
- 表示してよいもの:
  - 記憶状態
  - 次回手入れ目安
  - 写真登録状況
  - 庭園上の状態
- 主導線:
  - `思い出す / 復習する`
  - `図鑑を見る`
  - `閉じる`
- 図鑑へ移動しても、保護中は主要暗記情報を伏せた状態を維持する。
- `幽香に訊く` を選べば通常図鑑情報を表示し、`relearnedAt` を更新する。

### 設計意図
**確定**
ユーザー向けルールは次の3点に単純化する。
1. 普段の図鑑閲覧は自由。
2. 復習が近づくと、暗記情報だけ自動で伏せられる。
3. 見たければ幽香に訊ける。ただし、答えを確認した直後は本番復習の効果が薄くなり、翌日以降の復習が推奨される。

- 「どの問題形式を見たか」の複雑なルールをユーザーへ意識させない。
- 目的はテストを厳格化することではなく、自然な間隔を空けた復習を促すこと。

# 18. 学習モード / 「咲かせる」

## 基本思想
**確定**
- 「何のために問題を解くか」と「どう解くか」を分離する。
- 本作で**記憶維持の正式判定を行うのは復習**。
- 演習は任意の自主練であり、やる気がある時に量を回すための機能。
- 演習しなくても庭の維持には正式復習が必要なため、自然な復習圧が生まれる。
- ただし復習を罰ゲーム化せず、「今日は特に必要なし」となる日も作る。

## 「咲かせる」— 新規学習
**確定**
- 未開花・育苗中の属を開花へ持っていくための学習。
- 必須3形式の未クリア項目を優先して出題する。
- 1形式初正解 → 育苗開始 / 芽。
- 2形式初正解 → 成長。
- 3形式初正解 → 開花。
- 開花まではテンポを重視し、「記憶を測る」より「記憶を作る」ことを優先。
- 必要に応じて図鑑や情報隠しモードを併用してよい。
- ホーム上の主導線名称は **「咲かせる」** を第一候補とする。
- 園芸概念上は **記憶播種 → 育苗 → 開花** に対応。

## 「演習」— 任意の自主練
**確定**
- 好きな属・範囲・問題形式を選び、好きなだけ練習する。
- 正答率・回答履歴などは記録してよい。
- **演習で正解しても正式な復習段階は進めない。**
- 復習保護期間中の属を演習し、正答を確認した場合は、その属に `relearnedAt` を記録する。
- `relearnedAt` から約24時間は正式復習の段階アップ・期限延長を行わない。
- 復習保護期間より十分前の演習は、自由な自主学習として扱う。
- これは罰ではなく、「答えを見た直後ではなく、時間を空けても思い出せるか」を正式復習で判定するため。
- **即答は独立モードにせず、演習等に付けるオプション**とする。
  - 例: 即答モード ON / 5秒 / 10秒 / 15秒。
  - 時間切れは演習上の不正解扱いとしてよいが、復習段階には直接影響させない。

## 「手入れする」— 正式復習
**確定**
- 開花済み植物の記憶維持を判定する、本作における正式な復習。
- 庭の鮮やかさ・復習間隔を本格的に回復／延長できるのは原則このルート。
- 正式復習の主導線は下部タブ **「手入れ」** に集約する。
- 園芸概念上は **記憶灌水** に対応。
- おまかせ復習では期限切れ・期限間近を優先し、最大5属程度を提示。
- 先のものしかなければ「今日は特に必要なし」としてよい。
- 自由復習では任意の属を選べるが、早すぎる復習では段階を進めない。

## 正式復習では1属につき原則1形式
**確定**
- 維持復習で同じ属の3形式を同一セッションに連続出題しない。
- ある問題文や正答が、直後の別形式の答えを教えてしまうため。
- 次回以降に別形式を回し、長期的に3形式すべてを維持する。
- 次回の形式選択では以下を組み合わせる。
  - 前回から最も空いている形式
  - 正答率が低い形式
  - 単純なローテーション
- これにより復習負債を抑えつつ、3方向の想起を維持する。

## 役割の要約
**確定**
- **咲かせる** = 記憶を作り、開花させる。
- **演習** = 任意で量をこなす。正式な延命判定ではない。
- **手入れする** = 時間を空けた自力想起で、記憶を正式に維持する。

## 7 「咲かせる」開始フロー / 予習スキップ

### 基本フロー
**確定**
ホームの `咲かせる`
→ 学ぶ属を選ぶ
→ 予習画面
→ 確認問題
→ 成長 / 開花
→ 開花時は定植へ

- 予習は推奨するが、**必須にはしない**。
- 既に知っている属・直前に図鑑で確認した属について、毎回予習を強制しない。

### 入口の見せ方
**確定方針**
- 開始時に大きな2択ダイアログを毎回出すより、**予習画面へ自然に入り、そこに明確なスキップ導線を置く**方式を第一候補とする。
- 理由:
  - 画面遷移が単純になる。
  - 初見ユーザーは自然に予習へ入れる。
  - 慣れたユーザーは1タップで問題へ進める。
  - 毎回「予習する / すぐ問題」の選択を要求しないためテンポが良い。

推奨UI:
- 予習画面右上または下部に `もう覚えている` / `問題へ` を表示。
- 主ボタンは `覚えた。問題へ`。
- 補助導線として `予習を飛ばす` を用意してもよい。
- 文言は実機で自然なものへ調整する。

### 予習画面
**確定**
- 図鑑詳細の情報を利用するが、通常の図鑑タブとは別の**学習セッション内ビュー**として表示してよい。
- 最低限、今回の必須3形式に必要な情報を読みやすく提示する。
- 写真・特徴・備考も表示可能だが、情報過多にはしない。
- `次へ` で確認問題へ進む。
- 予習中に情報を見ても、新規学習中なので `relearnedAt` 等の復習保護ロジックは適用しない。
- これは「記憶を作る」工程であり、正式復習とは別。

### スキップ時
**確定**
- `問題へ` / `予習を飛ばす` を選ぶと、そのまま未クリア形式の確認問題へ進む。
- スキップによるペナルティはなし。
- 既知知識で正解した場合も、通常どおりその形式を初回クリアとして数える。
- 不正解時は正答を表示し、その後同セッション内で再挑戦可能。

### 再挑戦
**確定方針**
- 開花学習では、不正解した形式をその場で何度でも再挑戦できる。
- ただし同じ問題を即座に丸暗記で再入力するだけにならないよう、以下のいずれかを使う。
  - 他形式を1問挟む
  - 短い説明 / 図鑑確認を挟む
  - 数問後に再出題
- 開花までのテンポを悪くしすぎない。

# 19. 演習モード

## 役割
**確定**
- 演習は、好きな範囲を好きなだけ解くための**任意の自主練習**。
- 図鑑と同じく「学び直す」側の機能であり、正式復習とは分離する。
- 演習で正解しても:
  - 正式復習段階は進まない。
  - 次回正式復習期限は延びない。
  - 庭上の超過状態は巻き戻らない。
  - 開花前の必須3形式クリアにも数えない。
- 演習は庭維持の正式判定ではなく、純粋な練習量を増やすための機能。

## 主な入口
**確定方針**
- ホーム画面へ演習専用の常設ボタンは置かない。
- 主な入口は図鑑側とする。
  - 図鑑一覧の `演習`
  - 図鑑詳細の `この属を演習`
  - 検索 / フィルターした範囲から `この範囲で演習`
- 必要なら `手入れ` 内から「追加で練習する」導線を出してよいが、正式復習とは明確に区別する。
- ホームの庭景観を演習導線で混雑させない。

## 演習セットアップ
**確定**
開始前に選べる項目:
- 対象範囲
  - 全属
  - 科
  - 庭園所属
  - お気に入り
  - 検索 / フィルター結果
  - 個別に選択
- 出題属数
  - ダイヤル / ステッパー等で選択
- 問題形式
  - チェックボックスで複数選択
  - `属→科`
  - `和名→Latin`
  - `Latin→和名`
  - 写真問題（利用可能な場合）
- 即答オプション
  - OFF / 5秒 / 10秒 / 15秒等

**確定方針**
- 演習は「問題形式を複数選んで量を回す」用途を重視する。
- 同一属で複数形式を続けて出してもよい。
- 正式復習とは違い、問題同士の答え漏れは演習上の問題としない。

## 復習保護との関係
**確定**
- 演習も答えを見られるため、復習直前の扱いには注意する。
- **復習保護中の属は、通常の演習候補からデフォルトで除外する。**
- セットアップ画面では必要に応じて:
  - `復習が近い属を含める`
  の明示的なオプションを用意してよい。
- 保護中の属を演習対象に含める場合は、短い説明を一度だけ表示する。
  - 例: `この属は復習が近いので、今練習すると本番の効果は明日まで弱くなります`
- 長い警告ダイアログを毎回出さない。

## 演習中に答えを見た場合
**確定**
- 復習保護期間中の属で演習し、正答表示を見た場合は `relearnedAt` を更新する。
- その後約24時間:
  - おまかせ復習から原則除外
  - 正式復習しても段階アップなし
  - 次回期限延長なし
- 復習保護期間より十分前の演習は通常の自主学習として扱う。
- その後、正式復習まで24時間以上空けば通常効果で復習できる。

## 開花前の属を演習した場合
**確定**
- 未着手・育苗中の属も演習対象に含められる。
- ただし演習正解は**開花進捗へ反映しない**。
- 開花させたい場合は `咲かせる` から正式な新規学習へ進む。
- 演習終了後に未開花属が含まれていた場合、必要なら `この属を咲かせる` への導線を出してよい。

## 演習結果
**確定**
演習終了時に表示してよいもの:
- 問題数
- 正解 / 惜しい / 不正解
- 問題形式別正答率
- 苦手だった属
- 平均回答時間（即答ON時など）

**確定**
- 演習成績は正式復習成績と分けて記録する。
- `practiceAccuracy` と `reviewAccuracy` 等を別管理する。
- 演習正答率を正式復習の間隔計算へ直接利用しない。
- 苦手形式の参考情報として利用する場合も、正式復習履歴を優先する。

## 問題画面
**確定**
- `咲かせる / 手入れ` と同じ共通問題UIを再利用する。
- 上部表示だけ `演習` に切り替える。
- 即答ON時のみ時間ゲージを表示する。
- 幽香は通常問題の読み上げ役ではなく、回答結果へ短く反応する。

## 写真問題
**確定**
- 写真登録済みの属は演習でも写真問題を選べる。
- 演習で写真問題に正解しても、正式復習時の「次回間隔+5%」ボーナスは発生しない。
- 写真問題ボーナスは正式復習内で解いた場合のみ。

## 設計思想
**確定**
- 演習は「やる気がある日にたくさん勉強できる」自由枠。
- 正式復習は「時間を空けても覚えていたか」を判定する本番。
- 演習を頑張ったことで庭維持が直接免除される設計にはしない。
- 一方で、復習直前にうっかり演習して本番効果を潰す事故は、保護中属をデフォルト除外することで防ぐ。

# 20. 問題入力 / キーボード / 採点

## 基本方針
**確定**
- 入力仕様は「元資料に記載された正答文字列」を基準とする。
- 採点のために植物名そのものを別表記へ勝手に置き換えない。
- ただし、入力上の表記ゆれ・不要な接尾辞・全角半角等は、ユーザーの知識とは無関係なため正規化してよい。
- 正式な学習・演習・復習では、**予測変換やサジェストによって答えが見えてしまわない入力方式**を使用する。

## 日本語入力
**確定**
- 日本語の正式回答表記は**カタカナへ統一**する。
- 元資料の正答データも、採点時はカタカナ基準で比較する。
- ユーザーがひらがなで入力した場合は、内部でカタカナへ変換して採点してよい。
- 濁点・半濁点・長音等は元資料の表記を正答基準とする。
- 日本語入力UIはカタカナ入力を前提に設計する。

## 英字入力
**確定**
- ラテン語属名等の英字回答は**半角英字**を基本とする。
- 正答判定では大文字小文字を区別しない。
- 全角英字で入力された場合は半角へ正規化してよい。
- 前後の空白は無視する。
- 正答表示は元資料の正式表記をそのまま使用する。

## 「科」「属」等の接尾辞
**確定**
- 入力欄の外側に `科` / `属` を固定表示し、ユーザーは本体名称だけを入力する。
- 例:
  - `[ アジサイ ] 科`
  - `[ アジサイ ] 属`
- ユーザーがコピー＆ペースト等で `アジサイ科` / `アジサイ属` まで入力した場合は、末尾の接尾辞を取り除いて採点してよい。
- これにより、接尾辞の有無で不正解にしない。

## Enter / Return の挙動
**確定**
- 複数入力欄がある場合:
  - Enter / Return → 次の入力欄へ移動。
- 最後の入力欄の場合:
  - Enter / Return → キーボードを閉じる。
- Enterだけで回答送信はしない。
- 回答確定は画面上の `回答する` / `決定` ボタンで行う。
- これにより、改行キーの誤操作による意図しない送信を防ぐ。

## 複数回答欄の移動
**確定**
- キーボード上部のアクセサリーバーに `↑ / ↓` を表示する。
- `↑` → 前の入力欄。
- `↓` → 次の入力欄。
- 先頭 / 最後では無効表示。
- Enter / Return と同じフォーカス移動ロジックを使用する。

## 予測変換・サジェスト対策
**確定要件**
- 正式な学習・演習・復習では、入力候補から正答が見える状態を許容しない。
- 英字:
  - 自動修正
  - 自動大文字化
  - スペル候補
  - 予測候補
  を無効化した入力方式を使用する。
- 日本語:
  - iOS標準IMEで予測候補を完全に制御できない場合、**アプリ内の専用かな / フリック入力**を使用する。
- 実装方式はWork側で選定してよいが、Acceptance Criteriaは「正式問題中に答え候補が表示されないこと」。
- 図鑑検索・自由入力等、採点を伴わない画面では通常のシステムキーボードを使用してよい。

## 「惜しい」判定
**確定方針 / 閾値は暫定**
- 正規化後の正答文字列と入力文字列の編集距離を用いて判定する。
- 「惜しい」の上限は、**文字列長の15〜20%程度**を初期基準とする。
- 初期実装は20%を候補とし、実機で甘すぎる場合は15%へ下げる。
- 誤字・脱字・余分な1文字等を主な対象とする。
- 短すぎる文字列では1文字違いの影響が大きいため、最低文字数に応じた例外を設けてよい。
- 「惜しい」は正解ではない。
  - 開花条件の初回クリアには数えない。
  - 正式復習では段階アップしない。
  - 既定の「同じ段階でもう一度」ルールを適用する。

## 正規化処理
**確定**
採点前に以下を正規化してよい。
- 前後空白の除去
- 全角英数字 → 半角
- 英字の大文字小文字統一
- ひらがな → カタカナ
- `科` / `属` 等、入力欄外に固定表示している接尾辞の除去
- Unicode上の同等文字の標準化

**禁止**
- 元資料にない別名・俗称を勝手に正解扱いしない。
- 植物学的に正しいという理由だけで、元資料の正答データを自動修正しない。
- 別綴り・異表記を許可する場合は、正答データ側に明示的な別解として登録する。

## 採点結果
**確定**
採点結果は基本3種。
- 正解
- 惜しい
- 不正解

- 空欄は不正解。
- 複数回答問題では、必要に応じて各欄ごとの結果と問題全体の結果を分けて保持する。
- 正答表示は必ず元資料の正式表記を使う。

# 21. 問題回答画面 / 共通レイアウト

## 基本方針
**確定**
- `咲かせる / 演習 / 手入れ` は、可能な限り同じ問題回答画面の骨格を再利用する。
- 画面上部のモード表示・進捗・タイマー有無だけを切り替え、操作方法は統一する。
- 問題回答中は集中セッションとして扱い、**下部タブを非表示**にする。
- 左上の戻るのみ残す。

## 上部ヘッダー
**確定**
- 左上: 戻る
- 中央: モード名
  - `咲かせる`
  - `演習`
  - `手入れ`
- 右上: セッション進捗
  - 例: `3 / 8`
- `咲かせる` では、開花までの3段階進捗を小さく表示する。
- RPG的な経験値バーではなく、芽→成長→開花を感じられる植物的な表現を優先する。
- 即答オプションON時のみ、上部に細い時間ゲージを追加する。

## 問題領域
**確定**
- 中央に、植物標本帳・観察ノートを思わせるマットな問題面を置く。
- 問題文は短く簡潔にする。
- 例:
  - `科名を答える`
  - `ラテン語属名を答える`
  - `属和名を答える`
- 毎回長い説明文を表示しない。
- 問題の核となる語を大きく表示する。
- 通常の必須3形式では、写真は原則表示しない。
- 写真は写真問題として別の価値を持たせる。

## 回答欄
**確定**
- 科名:
  - 入力本体と接尾辞 `科` を分離して見せる。
  - 例: `[ アジサイ ] 科`
- 属名:
  - 必要に応じて `属` を欄外表示。
- ラテン語:
  - 英字入力。
  - 正答判定では大文字小文字を区別しない。
  - 前後空白・全角英数字等を正規化する。
- 問題形式に応じて適切なキーボードへ自動切替する。

## 幽香の表示
**確定**
- 庭では約5頭身の全身モデル。
- 学習画面では**腰上〜太腿程度の表示**へ切り替えてよい。
- 右下または左下の空き側へ配置する。
- 幽香は通常問題の読み上げ役にはしない。
- 回答前は静かに待機。
- 正解 / 惜しい / 不正解時のみ、表情・短い台詞で反応する。
- 問題文・入力欄・キーボードを隠さない位置へ適応配置する。

## 回答結果
**確定**

### 正解
- 入力欄周辺に控えめな正解表示。
- `咲かせる` で成長段階が進む場合は、小さな植物表示を一段成長させる。
- 派手な発光・粒子は使わない。
- 約0.8〜1.2秒後に自動で次へ進める方式を候補とし、タップですぐ進めてもよい。

### 惜しい
- 入力した答えを残す。
- 正答との差分を控えめに強調する。
- 開花条件の初回クリアには数えない。
- 正式復習では既定の「段階維持」ルールを使用する。

### 不正解
- 正答を明確に表示する。
- 自動で即次問へ飛ばさず、正答を確認できる一拍を置く。
- 新規学習では強い失敗演出を使わない。
- `次へ` で進行する。

## 開花学習の成長表示
**確定**
- 1問ごとの正答数を前面に出すより、植物の成長を感じる表示を優先する。
- 内部的には3形式のクリア状態を保持する。
- 画面上では:
  - 1形式クリア → 芽 / 初期成長
  - 2形式クリア → 成長
  - 3形式クリア → 開花 / 成熟
- 3形式目の正解時のみ少し特別な演出を行う。
- 演出は静かで園芸的にし、魔法的にしない。

## 開花直後
**確定**
- 開花 / 成熟達成を表示。
- 幽香が少し特別な反応をしてよい。
- その後:
  - `幽香に任せる`
  - `中央庭園に置く`
  - `自分で植える`
  へ接続する。
- 開花後の配置選択は、同セッションの自然な終端として扱う。

## セッション終了 / 中断
**確定方針**
- 問題回答中は下部タブを表示しない。
- 左上戻るを押した場合:
  - 回答途中なら `ここまでを保存して終了 / 続ける` 等の簡潔な確認。
- 既に確定した正解・進捗は保存する。
- 未送信の入力内容だけは破棄してよい。
- セッション終了後、元の導線に応じてホーム・図鑑・手入れへ戻す。

## ビジュアル方針
**確定**
- 庭より集中寄り。
- 植物標本帳・観察ノートの意匠。
- 生成り・紙・くすんだ緑等を基調にし、可読性を優先。
- 金属光沢や派手な縁取りは使わない。
- 庭と同じアプリのデザイン言語は維持する。

# 22. 写真 / 観察記録 / 外観バリエーション

## 写真登録の基本
**確定**
- 写真登録は任意。
- 写真がなくても開花・定植・通常復習は可能。
- 写真登録済みの属には「観察済み」状態を付与する。
- 写真登録は、単なる収集要素ではなく庭の見た目を豊かにする要素へ接続する。

## 写真登録ボーナス
**確定**
- 写真登録により、該当属の**外観バリエーション**を解放できる。
- 外観バリエーションは「花色」だけに限定しない。
- 属に応じて以下を扱える。
  - 花色
  - 葉色
  - 斑入り
  - 葉脈・模様
  - 樹形
  - その他、園芸的に自然な差分

## バリエーションの制約
**確定**
- 自由なカラーピッカーは使用しない。
- 実在の園芸品種、自然変異、園芸上一般的に存在する範囲に基づく候補だけを提供する。
- 植物図鑑として不自然な色・模様は作らない。
- 各属に `appearanceVariants` を持たせ、解放可能な差分をデータで管理する。
- 写真の色を自動解析して即座にモデルへ反映する機能は初期実装では不要。

## 写真登録時の体験
**確定方針**
写真登録
→ 「観察済み」付与
→ その属の外観バリエーション候補を解放
→ ユーザーが庭モデルの外観として選択可能

- 複数写真登録により追加バリエーションを段階解放する仕組みは将来拡張として許容する。
- v1では、最低1つの追加外観を解放するだけでも成立する。

## 写真問題
**確定**
- 写真問題は、写真登録済みの属で利用可能。
- 必須3形式とは別の復習手段。
- 正式復習内のボーナス写真問題に正解した場合、**新しく設定された次回間隔を初期値5%延長**する。
- 写真問題で不正解でも、通常の正式復習結果へ追加ペナルティは与えない。
- 演習として解いた写真問題では、この間隔ボーナスを発生させない。
- 写真問題の役割:
  - 写真登録によって庭の見た目を豊かにする
  - 実物識別を鍛える
  - 正式復習に小さな追加報酬を与える

## 将来拡張
**将来拡張**
- 撮影 → EXIF日時 / GPS取得 → 図鑑登録の自動化
- 写真から候補属を提示する補助
- 観察記録の時系列表示
- 同属の複数観察記録

## ロゴ / アプリアイコン

### 基本方針
**確定**
- ロゴとアプリアイコンは役割を分ける。
- ロゴは作品名と世界観を伝える。
- アプリアイコンは小さい表示でも一目で識別できることを優先する。
- 両者とも、庭の落ち着いた雰囲気に合う**静かな上品さ**を重視する。
- メタリック感・過度な装飾・ゲームアプリ的な派手さは避ける。

### アプリ名表記
**確定**
- 正式ロゴ表記:
  - **千花之恋図鑑**
  - 小さく **Garden of memory**
- 読み:
  - **せんかのこいずかん**
- ホーム画面のアプリアイコン下表示は:
  - **千花之恋図鑑**
- `Garden of memory` は主に起動画面・ロゴ表示・設定画面等で使用する。

### ロゴの方向性
**確定方針**
- 和文メイン。
- 主タイトルは上品で可読性の高い明朝寄りセリフ体を基調とする。
- 英文サブタイトルは細めのセリフ体または控えめなイタリックで添える。
- ロゴ単体で「重厚な幻想作品」になりすぎず、「静かな図鑑・庭園」の印象を優先する。
- 主タイトルを読ませるロゴであり、極端に崩した装飾文字は使わない。

### ロゴモチーフ
**確定方針**
- 文字だけのロゴにせず、小さなモチーフを添えてよい。
- 候補:
  - 一輪の花
  - 葉と蔓
  - 標本ラベル風の飾り
  - 小さな庭門 / 額縁風の囲み
- ただし、複雑な紋章化はしない。
- モチーフは補助的なもので、主役はタイトル文字。

### アプリアイコンの原則
**確定**
- アプリアイコンでは**文字を詰め込みすぎない**。
- フルタイトルをアイコン内へ入れない。
- 1〜2要素で識別できる構成にする。
- 小サイズでも潰れないことを優先する。
- 幽香の全身像や細かい背景を詰め込まない。

### アイコン候補コンセプト
**確定方針**
候補は以下3系統。

#### A. 一輪の花エンブレム
- 深い緑〜青緑系の背景
- 中央に一輪の花
- 控えめな細枠
- 最も素直で識別しやすい

#### B. 図鑑 / 標本帳モチーフ
- 開いた本 or 標本帳の抽象化
- その上に花・葉の記号
- 「図鑑」と「植物学習」の性格が伝わる

#### C. 庭門 / 額縁 + 花
- 枠の中に花や葉
- 「庭園」感が少し強い
- 装飾しすぎると小サイズで潰れやすいため注意

### 推奨コンセプト
**推奨**
- 第一候補は **A. 一輪の花エンブレム**
- 次点で **B. 図鑑 / 標本帳モチーフ**

理由:
- 小サイズで最も読み取りやすい。
- 幽香や複数の花を詰め込むより視認性が高い。
- アプリの中身が庭メインでも、ホーム画面の識別には単純さが有利。
- ロゴ側で世界観を補えば、アイコンは単純でも弱くならない。

### アイコンに幽香を使うか
**確定方針**
- 幽香をアプリアイコンの主役にはしない。
- 理由:
  - 顔や衣装の細部が小サイズで潰れやすい
  - 最終アート確定前だと差し替えの影響が大きい
  - ホーム画面で「植物アプリ」と認識されにくくなる
- 将来サブアイコン機能を使うなら、幽香版を追加してよい。
- ただし初期の標準アイコンは植物モチーフを優先する。

### 色方針
**確定方針**
候補色:
- 深緑
- くすんだ青緑
- 落ち着いた生成り / 花の淡色
- 控えめな金 / 真鍮色のアクセント

- 派手な原色や高コントラスト過多は避ける。
- UI同様、背景との調和を重視する。
- 明暗差は十分確保し、暗い壁紙でも埋もれないようにする。

### 起動画面でのロゴ表示
**確定**
- 起動画面ではロゴを中央に静かに表示する。
- アイコンの図案をそのまま拡大流用してもよいが、ロゴでは正式タイトルを明確に読ませる。
- 起動画面のロゴは、アイコンよりも少し繊細な装飾を許容する。
- 背景は無地〜ごく薄い模様程度に留める。

### 将来の制作手順
**確定**
1. 仮ロゴ / 仮アイコンを簡易デザインで作る
2. 実機でホーム画面上の視認性を確認する
3. 起動画面・設定画面に置いてバランス確認
4. 必要なら文字比率・枠・花モチーフを調整
5. 最終版を作成する

### v1ブランド方向の確定
**確定**

#### アプリアイコン A
- 深緑〜青緑の背景。
- 中央に、やや図案化した**ヒマワリ系の一輪花エンブレム**。

# 24. アニメーション / 描画基盤

## 基本方針
**確定**
- 庭全体は「静止画」ではなく、微細な連続アニメーションを持つ。
- ただし常時派手に動かさず、落ち着いて眺められることを優先する。
- コマアニメーションと連続補間を役割分担する。

## 幽香の歩行
**確定方針**
- 歩行ポーズ自体はスプライトのコマアニメーションでよい。
- 1歩行周期あたり8〜12枚程度を初期目安とする。
- 再生は約12〜18fps程度を初期目安とする。
- キャラクターの画面上の座標移動はコマ切り替えとは分離し、60fps相当の連続補間で滑らかに動かす。
- そのため、歩行絵の枚数が少なくてもキャラクター自体がガクガク瞬間移動する見た目にはしない。
- 初期方向差分は3〜4方向程度を候補とし、左右反転可能な素材は反転を利用する。
- 8方向すべてを初期必須にはしない。

## 待機モーション
**確定方針**
- 待機時は、呼吸、瞬き、視線、髪、服、小物等の微動作を中心にする。
- 全身の大きなループアニメーションを常時再生しない。
- 幽香が「その場にいる」感覚を優先する。

## 植物
**確定方針**
- 植物の風揺れは、可能な限りコマアニメではなく連続値で処理する。
- 茎・葉・花・花序等のパーツ単位に、わずかな回転・変位を与える。
- 植物ごとに周期・位相・振幅を少しずらし、全植物が同じ動きをしないようにする。
- 背の高い植物ほど上部の揺れを大きくし、低木・草本・大型葉など形態差を反映できる構造にする。
- 30〜60fps相当の滑らかさを目標とする。

## 水面・環境
**確定方針**
- 水面の反射、微かな波紋、水草等は連続アニメーションで表現する。
- 常時派手な粒子・花弁エフェクトは使用しない。
- 環境アニメーションは、全画面鑑賞モードで眺めて楽しめる程度の存在感にする。

## 技術選定
**確定方針**
- 図鑑・学習・タブ・情報パネル等はSwiftUIを継続利用してよい。
- 庭画面は、植物・幽香・z順・座標移動・タップ判定・微アニメーションを扱いやすくするため、**SpriteKit等の2Dシーン描画基盤をSwiftUIへ埋め込む構成を第一候補**とする。
- 実装前に既存コードとの統合コストを確認し、同等の性能・保守性が得られる別方式がある場合は代替可。
- ただし「庭をSwiftUIの静的Viewだけで無理に再現する」ことを必須条件にはしない。

# 25. 保存 / データ管理 / 移行

## 基本方針
**確定**
- アプリは**ローカルファースト**で動作する。
- 学習・復習・庭園・図鑑の主要機能は、ネット接続なしでも利用できることを基本とする。
- 307属の基礎データはアプリ同梱の読み取り専用マスターデータとして扱い、ユーザー進捗とは分離する。
- ユーザーの進捗・庭配置・写真・設定は別の永続データとして保存する。
- 画面を閉じた、アプリが中断された、端末が再起動した等で学習進捗が失われないことを優先する。

## 保存するユーザーデータ
**確定**
最低限、以下を永続化する。

### 学習 / 開花
- 必須3形式それぞれの初回クリア状態
- 育苗段階
- 開花済みフラグ / 開花日時
- 新規学習の途中状態（確定済み回答のみ）

### 正式復習
- 現在の復習段階
- `nextReviewAt`
- `lastFormalReviewAt`
- `relearnedAt`
- 現在段階で早期復習ボーナスを使用済みか
- 正式復習の正解 / 惜しい / 不正解履歴
- 必要な最小限の問題形式履歴

### 演習
- 演習回数
- `practiceAccuracy`
- 問題形式別の演習履歴
- 回答時間等、演習結果画面で利用する情報

### 庭園
- `assignedGardenID`
- `displayZoneID`
- `displaySlotID`
- `placementAuthority`
- `isDisplayPinned`
- `isFavorite`
- 各庭園 / 特殊庭園の解放状態
- 未確認解放イベント
- 植栽編集の確定済み配置

### 写真 / 外観
- 写真登録状態
- 写真ファイルへの参照
- 観察日時等、ユーザーが保存した情報
- 解放済み `appearanceVariants`
- 現在選択中の外観バリエーション

### 初回案内 / イベント
- 既読チュートリアル
- Level A 初回案内の既読状態
- 最近の出来事
- 季節イベント等の必要な進行状態

### 設定
- 通知
- サウンド
- 触覚
- 表示
- その他ユーザー設定

## 保存タイミング
**確定**
- 大きなセッション終了時だけにまとめて保存しない。
- 以下の**意味のある確定操作ごと**に保存する。
  - 問題回答を確定した
  - 開花した
  - 正式復習結果が確定した
  - 写真を登録した
  - 外観を変更した
  - 区画を解放した
  - お気に入りを変更した
  - 設定を変更した
  - 植栽編集で `完了` を押した
- 保存処理は原則としてユーザー操作を止めない。

## 植栽編集のトランザクション
**確定**
- 植栽編集開始時に現在の配置を作業用コピーへ複製する。
- 編集中のドラッグ操作は作業用コピーへだけ反映する。
- `完了` を押した時点で、配置変更を**一括コミット**する。
- `戻る → 変更を破棄` では永続データを変更しない。
- 保存途中で失敗した場合、半端な配置状態を残さず編集前の確定状態を維持する。
- 直後Undoを実装する場合は、直前の確定配置スナップショットを短時間保持する。

## 問題セッション中断時
**確定**
- 一度確定した回答結果は、その都度保存する。
- 未送信の入力文字列は保存必須ではない。
- アプリ中断・強制終了後に再起動した場合:
  - 確定済み進捗は失わない。
  - 未回答問題からセッション再開、またはセッションを終了してもよい。
- 「8問中7問まで答えたのに全部消えた」を起こさない。

## データスキーマのバージョン管理
**確定**
- 永続データには `schemaVersion` を持たせる。
- アプリ更新でデータ構造が変わる場合は、起動時に旧バージョンから新バージョンへ移行する。
- 新しい属性・庭園・問題形式を後から追加しても、既存ユーザーデータを破棄しない構造にする。
- 307属のマスターデータ更新とユーザー進捗更新を分離する。

## 既存アプリからの移行
**確定方針**
- 現行プロトタイプに保存済みユーザーデータが存在する場合、可能な限り引き継ぐ。
- 最低限、以下は移行候補:
  - 3形式のクリア状態
  - 開花状態
  - 学習 / 回答履歴
  - 写真
  - お気に入り
- 新仕様に存在しない旧データ項目は、即削除せず移行処理中に安全に無視・変換する。
- 旧データ形式の実体をWorkが確認し、移行可能項目と不可能項目を実装前に一覧化する。
- 移行不能な項目がある場合は、黙って破棄せず実装報告へ明記する。

## バックアップ / 書き出し
**確定方針**
- ユーザー進捗をアプリ外へ退避できる**書き出し / 読み込み機能**を用意する。
- 初期実装では、専用バックアップファイルとして書き出せればよい。
- バックアップには最低限:
  - ユーザー進捗
  - 庭配置
  - 解放状態
  - 設定
  を含める。
- 写真をバックアップへ含める場合は、メタデータだけでなく実ファイルも失われない形式を優先する。
- バックアップ形式には `schemaVersion` とアプリバージョン情報を含める。
- 読み込み前には既存データを上書きすることを明示し、必要なら自動的に現状バックアップを作成する。

## iCloud等のクラウド同期
**将来拡張**
- v1では必須としない。
- ローカルデータ＋手動バックアップで成立させる。
- 将来、複数端末利用が必要になった場合にiCloud等を追加できる構造は残す。
- クラウド同期を前提にアプリの基本機能を設計しない。

## 写真ファイル
**確定方針**
- 写真は永続保存領域へ管理し、一時キャッシュだけに置かない。
- DB等には画像バイナリを大量に直接埋め込まず、ファイル参照＋メタデータで管理する方式を第一候補とする。
- 写真削除時は、図鑑からの参照と実ファイルの整合を取る。
- 将来EXIF日時・位置情報等を使う場合も、ユーザーが明示的に必要とした情報だけを保存する。

## データ破損対策
**確定**
- 保存は可能な限り原子的に行う。
- 永続データ読込に失敗した場合、即座に空の新規データで上書きしない。
- バックアップ / 旧ファイル / 復旧可能なスナップショットがあれば復旧を試みる。
- 復旧不能な場合は、ユーザーへ状態を明示する。
- デバッグ用途を除き、ユーザー進捗を自動的に全消去しない。

## リセット
**確定方針**
- 設定画面からデータリセットを行えるようにしてよい。
- 誤操作防止のため、即時1タップ全消去にはしない。
- 最終確認を必須とする。
- 将来的には以下を分離してよい:
  - 学習 / 復習進捗のみ
  - 庭配置のみ
  - 写真のみ
  - 全データ
- v1で分離リセットが重い場合は、まず全データリセットのみでもよい。

## Acceptance Criteria
**確定**
- 問題回答確定後にアプリを強制終了しても、その回答結果が失われない。
- 植栽編集で `完了` 前に終了した場合、未確定変更が本配置を壊さない。
- アプリ更新時に、旧ユーザーデータを理由なく初期化しない。
- 307属マスターデータ更新でユーザー進捗が失われない。
- 写真登録後、通常のアプリ再起動で写真参照が切れない。
- バックアップ書き出し後、同バージョンで読み戻して主要進捗を復元できる。

# 26. 設定 / 通知 / アクセシビリティ

## 設定画面の役割
**確定**
- 設定画面は機能を増やしすぎず、日常利用で必要な調整だけをまとめる。
- 主なカテゴリ:
  - 通知
  - サウンド
  - 触覚
  - 表示 / アニメーション
  - 復習補助
  - データ / バックアップ
  - アプリ情報
- 初期状態で細かい上級設定を大量に見せない。
- 高度な調整項目は必要なら「詳細設定」へまとめる。

## 通知
**確定**
- 通知は**任意ON**。
- 初回起動直後にOS通知許可を要求しない。
- ユーザーが設定画面で通知をONにした時、初めてOS許可を求める。
- 通知は原則**1日1回まで**。
- 正式復習対象がある日だけ通知する。
- 復習対象がない日は通知しない。
- 放置日数に応じて通知回数を増やさない。
- 同日に複数回の催促をしない。

## 通知時刻
**確定**
- ユーザーが通知時刻を選べる。
- 初期候補時刻はアプリ側で提示してよいが、自動的に通知を有効化しない。
- 通知予定時刻より前にその日の「今日の手入れ」を完了した場合、その日の通知は送らない。
- `relearnedAt` により本番復習を翌日へ回している植物しかない場合は、その植物のためだけに通知しない。

## 通知文
**確定方針**
- 圧を強くしない。
- 期限超過数や負債件数を通知本文で強調しない。
- 例:
  - `そろそろ手入れどきの植物があります`
  - `庭を少し見ていきませんか`
- 幽香の正式な通知文は後で台詞として詰める。
- 「○件未処理」「連続○日失敗」等の罪悪感を煽る文言は使わない。

## アプリアイコンのバッジ
**暫定**
- バッジは通知設定とは別にON/OFFできるようにしてよい。
- 初期OFFを推奨。
- ONの場合も、件数を大きく積み上げるより `1` など「手入れ対象あり」の存在だけを示す方式を優先する。
- 復習負債の総数をホーム画面・アプリアイコンへ常時表示しない。

## サウンド
**確定方針**
個別に調整可能にする。
- BGM
- 環境音
- 効果音

**確定**
- 庭の環境音は重要だが、常時必須ではない。
- 起動時に突然大音量で再生しない。
- 端末のサイレント / 音量設定を尊重する。
- 幽香のボイス実装はv1必須ではない。台詞はテキストだけで成立させる。

## 触覚フィードバック
**確定**
- ON / OFFを設定できる。
- 主な利用箇所:
  - 植物の長押し持ち上げ
  - 有効スロットへの吸着
  - 回答確定
  - 重要な軽いUI反応
- 連続的な振動や強い触覚を多用しない。

## 表示 / アニメーション
**確定**
- `アニメーションを減らす` 設定を用意する。
- ONの場合:
  - 幽香の長い歩行入場を短縮
  - カメラズーム遷移を短縮 / フェードへ置換
  - 植物の風揺れを弱める
  - 水面等の連続動作を簡略化
- 重要な状態変化は、アニメーションを減らしても理解できること。
- OSの「視差効果を減らす / Reduce Motion」等が取得可能な場合は尊重する。

## 文字と可読性
**確定**
- Dynamic Type等、端末の文字サイズ設定を可能な範囲で尊重する。
- 大きな文字サイズでも主要操作が画面外へ押し出されないようにする。
- テキストと背景のコントラストを確保する。
- 庭に馴染ませるために可読性を犠牲にしない。

## 記憶状態を色だけに依存しない
**確定**
- 記憶状態は庭上で彩度・セピア・モノクロ等により表現するが、**色だけを唯一の情報源にしない**。
- 拡大観察 / 手入れ画面では必ず状態ラベルを併記する。
  - 安定
  - 手入れどき
  - 乾き始め
  - 色褪せ
  - かなり曖昧
- 必要に応じて輪郭、ぼやけ、軽いノイズ、透明度等も併用する。
- 色覚特性や画面環境が違っても、復習状態を判断できること。

## 復習保護の設定
**確定方針**
- 初期状態では復習保護をONにする。
- 通常ユーザーへ細かい保護時間設定を求めない。
- 詳細設定として将来:
  - 標準
  - 弱め
  - OFF
  を追加できる余地を残す。
- v1では「標準ON」固定でも成立する。
- 復習保護をOFFにしても、正式復習アルゴリズム自体は壊れない構造にする。

## 全画面鑑賞の表示設定
**暫定**
- 全画面鑑賞モードでの環境UI / 幽香の吹き出し有無を将来設定可能にしてよい。
- v1では既定仕様:
  - HUD非表示
  - 下部タブ非表示
  - システム通知非表示
  - 幽香の自然な低頻度発話は許可
で固定してよい。

## データ関連設定
**確定**
設定画面から以下へアクセスできる。
- バックアップを書き出す
- バックアップを読み込む
- データリセット
- 写真保存状態の確認
- アプリ / データバージョン情報

## アプリ情報
**確定方針**
表示候補:
- アプリ名
- `千花之恋図鑑` の読み: `せんかのこいずかん`
- バージョン
- データバージョン
- 利用している資料 / クレジット
- プライバシー情報

## Acceptance Criteria
**確定**
- 通知OFFでは復習通知を送らない。
- 復習対象がない日は通知しない。
- 1日に複数回催促しない。
- 手入れ完了後、その日の予定通知を送らない。
- 記憶状態を色だけ見なくても手入れ画面・拡大観察で判別できる。
- `アニメーションを減らす` 状態でも主要操作・状態遷移が理解できる。
- 大きな文字サイズで主要ボタンが操作不能にならない。

# 27. 幽香アセット / サウンド

## 基本方針
**確定**
- 既存のフリー立ち絵を無理にアニメーション対応へ加工する前提にはしない。
- 本作の幽香は、庭内で歩く・座る・花を見る・編集時に位置を変える等の用途があるため、**最初からアニメーション利用を前提に設計した専用アセット**を用意する方針を第一候補とする。
- キャラクター画像そのものとアニメーションロジックを分離し、後から別アセットへ差し替え可能な構造にする。
- 初期実装では仮素材でシステムを成立させ、最終アートが完成してから差し替えてよい。

## 推奨する表現の分離
**確定方針**
用途を2系統に分ける。

### A. 庭内モデル
- 約5頭身。
- 全身表示。
- 歩行、待機、座る、植物を見る、軽い作業等。
- 3〜4方向程度の方向差分を初期目安とする。
- 歩行は8〜12コマ程度のスプライトアニメーション、または同等の2Dリグ方式。
- 画面上の座標移動は連続補間で滑らかにする。

### B. 会話 / 学習画面用表示
- 腰上〜太腿程度。
- 表情・ポーズ差分を優先。
- 庭内モデルと同一アート資産を再利用できる場合は再利用する。
- ただし読みやすさを優先し、別解像度・別構図を持ってもよい。

## アセット制作方式
**推奨**

### 方式1: パーツ分け2Dリグ
- 推奨度: 高
- 胴体、頭部、前髪 / 後髪、顔パーツ、腕、手、服の可動部、脚、小物等をレイヤー分けして制作する。
- 待機、呼吸、髪・服の揺れ、視線等を滑らかに表現しやすい。
- 歩行だけ別スプライト列と組み合わせてもよい。

### 方式2: 手描きスプライト
- 推奨度: 中
- 各行動をコマアニメーションとして描く。
- 実装は比較的単純。
- 方向・行動が増えるほど制作枚数が増える。
- 最初から多数のアニメーションを用意しない。

### 方式3: 静止立ち絵の後付け変形
- 推奨度: 低
- 元絵がパーツ分けされていない場合、髪・服・腕等の分離が不自然になりやすい。
- 歩行や座りポーズへの転用に限界がある。
- フリー立ち絵を無理にこの方式へ変換することは推奨しない。

## v1最小アセット
**確定方針**
庭内:
- 通常立ち
- 歩行
- 花を見る
- 座る
- 編集ガイド位置用の立ち
- 軽い手入れ

表情:
- 通常
- 軽い笑顔
- 真面目
- 呆れ / 疑い
- 軽い驚き

- 必要になった時点で追加する。
- 素材がない `actionID / expressionID` は既存の近い状態へフォールバックする。

## 制作順
**確定**
1. 仮素材でCharacterAnchor・移動・z順・UI干渉を完成させる。
2. 最終的な幽香のデザイン方向を決める。
3. 正面 / 斜め方向の庭内モデルを制作。
4. 歩行・待機の最小アニメーションを制作。
5. 座る・花を見る・手入れを追加。
6. 学習画面用の表情・ポーズ差分を追加。
7. 実機で見て必要な差分だけ増やす。

## 権利とファイル管理
**確定方針**
- リポジトリへ同梱するアセットは、利用条件・加工可否・再配布可否を確認できるものだけにする。
- 個人端末だけで差し替える素材は、アプリ本体のコードと分離して管理できるようにする。
- 他者が制作した立ち絵を使う場合、アニメーション用の切り分け・加工が許諾範囲に含まれるか確認する。
- 将来公開・共有する可能性が少しでもある場合は、最初から差し替え可能なアセット構造を維持する。

## サウンドの補足
**確定方針**
- BGMはフリー音源・自作・利用許諾が明確な音源を前提とする。
- 記憶の庭園というコンセプト上、鳥の鳴き声や生活感の強い足音等を常時環境音として入れる必要はない。
- 環境音は:
  - 風
  - 葉擦れ
  - 水面
  - ごく軽い衣擦れ / 操作音
  等、抽象度の高い自然音を中心候補とする。
- 幽香の歩行足音は、世界観を損なう場合は非常に控えめにするか省略してよい。



## 仮素材から本番アートへ移行する方針
**確定**
- v1実装初期は、幽香の最終イラストを待たずに**仮素材でキャラクターシステムを完成させる**。
- AI生成画像を本番アートとして使用しない。
- 仮素材も、最終絵へ寄せる必要はない。役割は以下の検証に限定する。
  - 5頭身時の画面占有率
  - CharacterAnchor位置
  - 歩行速度
  - z順 / 植物との重なり
  - UI回避
  - 座る / 見る / 編集ガイド等の必要ポーズ
  - 学習画面での腰上表示サイズ
- 仮素材は単純なベクター、人型シルエット、簡易線画等でよい。
- 本番イラストへ置換した際にコード変更を最小化するため、仮素材も本番予定と同じアセットID・基準点・キャンバス比率で管理する。

## 本番アートを依頼する時の発注単位
**確定方針**
最終的なイラスト発注前に、アプリ側で以下を確定して「発注仕様書」として渡せる状態にする。

- 庭内モデル:
  - 約5頭身
  - 必要方向数
  - 基準キャンバスサイズ
  - 足元基準点
  - 歩行時の見切れ範囲
  - z順を考慮した髪・服の張り出し
- 必要Action一覧:
  - idleStand
  - walking
  - lookAtPlant
  - sitting
  - gardening
  - guide
- 会話 / 学習用:
  - 腰上〜太腿
  - 必要表情一覧
  - 必要ポーズ一覧
- パーツ分け方式:
  - 2Dリグ向けレイヤー分け
  - または手描きスプライト向けフレーム仕様
- 納品形式:
  - PSD等のレイヤー保持形式
  - PNG等の書き出し形式
  - 透過背景
  - ファイル命名規則
- 権利条件:
  - アプリ組み込み可
  - 加工可
  - アニメーション用パーツ分け可
  - 個人利用範囲
  - 将来共有 / 公開する場合の再契約条件

## 依頼時期
**確定**
- 本番イラストの発注は、CharacterAnchor・必要Action・画面上サイズ・方向差分が仮素材で検証できてから行う。
- 先に高価なアートを発注し、後から仕様変更で描き直しが発生することを避ける。
- 発注前に仮素材で最低1回、実機上のホーム・ゾーン観察・編集・学習画面を通して確認する。

# 28. 現行実装監査 / 再利用方針

## この監査の扱い
**確定**
- 2026-10-01時点の実機スクリーンショット群は、**現行プロトタイプの状態確認資料**として扱う。
- これらの画面デザイン自体を完成版のビジュアルリファレンスにはしない。
- 完成版は本仕様書のビジュアル方針を優先し、現行画面からはロジック・導線・データ構造の再利用可否だけを判断する。

## 現行ホーム画面
観察事項:
- 中央庭園が大きな矩形カード／楕円ゾーン群として表現されており、庭そのものが画面背景になっていない。
- 現在は「花を咲かせる」「庭を手入れする」の2ボタンがホームに存在する。
- 下部タブは `ホーム / 庭園 / 図鑑 / 記録`。
- 右端にスクロールインジケータが見え、ホーム全体が縦スクロール可能になっている。
- 背景と文字色のコントラストが不足しており、とくに白文字の視認性が低い。
- 幽香、実景の花壇、水辺、ベンチ、小道、育苗コーナーなど、完成版で重要な景観要素はまだプレースホルダー。

**完成版への指示**
- ホームはScrollViewで実装しない。
- 縦横スクロール・バウンスを禁止し、1画面に固定。
- 端末差はスクロールで吸収せず、Safe Area・相対レイアウト・スケール調整で吸収する。
- ホームの常設主ボタンは `咲かせる` を基本とし、正式復習は下部タブ `手入れ` に集約する。
- 現行の `記録` タブは完成版ナビゲーションでは `手入れ` に置換する前提。
- 庭の景観を主役にし、カード状の大きな背景パネルは使用しない。

## 現行庭園タブ
観察事項:
- 中央庭園内ゾーンは縦リストで並んでいる。
- 生態区画もロック付き縦リスト。
- 機能上はゾーン一覧・解放状況の確認画面として再利用可能。

**完成版への指示**
- `庭園` タブの役割は維持できる。
- ただし完成版では単純な設定リストだけでなく、区画マップ／庭園全体像など、庭を移動している感覚を持たせる。
- 生態区画の解放状態・移動先一覧という情報構造は再利用候補。

## 現行ゾーン拡大観察
観察事項:
- ゾーン画面への遷移と、観察→編集の分離は既に存在する。
- 植物配置領域は大きな楕円と点線スロットのプレースホルダー。
- 幽香の情報UI用領域らしきカードはあるが、低コントラスト。
- 「配置を編集する」ボタンは観察画面内に独立して存在している。

**完成版への指示**
- `ホーム → ゾーン拡大観察 → 明示的な編集ボタン → 編集` の構造は残す。
- 景観・植物・幽香の描画は全面的に差し替える。
- 観察画面では植栽スロットを通常表示しない。
- 植物をタップした時のみ対象強調、他植物低透明度化、幽香側情報表示を行う。

## 現行編集モード
観察事項:
- L×1 / M×2 / S×3 のスロット構成が実装されている。
- `戻る / 完了` が分離されている。
- 長押し移動・作業トレイの説明が存在する。
- 現状の作業トレイは実際の植物カードUIとしてまだ視覚化されていない。

**完成版への指示**
- スロットサイズ構成、`戻る / 完了`、編集セッションの分離は再利用候補。
- 下部に横スクロール植物トレイを実装し、長押し→ドラッグ＆ドロップを主操作にする。
- 編集画面の背景は観察時と同じゾーン景観を維持し、編集開始時に別世界へ切り替えない。
- スロット表示は編集時のみ出す。

## 現行図鑑一覧・詳細
観察事項:
- 307属一覧、検索、属名／和名／科名、習熟進捗を持つ。
- 図鑑詳細で3形式のクリア状態、正答率、学習記録が見られる。
- 情報隠し機能は既に実装されている。
- 暗色UIは視認性自体は比較的良いが、完成版の庭・園芸雑誌的ビジュアルとは別系統。

**完成版への指示**
- 検索・データ・情報隠し・詳細情報の機能は積極的に再利用する。
- ビジュアルのみ全体テーマへ統合。
- 復習保護期間中に `幽香に訊く` 等で主要暗記情報を開いた場合は、属単位で `relearnedAt` を記録する。

## 現行「記録」画面
観察事項:
- 記憶済み数、開花実績、苦手、写真登録、今日の回答、形式別正答率、学習履歴などが存在する。
- 完成版の下部タブとしては `記録` ではなく `手入れ` を採用する方針。

**完成版への指示**
- 現行の統計情報は削除せず、`手入れ` 内のサブ画面または図鑑・記録詳細へ再配置する。
- `手入れ` の第一目的は正式復習。統計は副次情報とする。

# 29. 画面スクロール / パン / ズーム方針

## ホーム
**確定**
- 縦スクロール: 禁止。
- 横スクロール: 禁止。
- パン: 禁止。
- ピンチズーム: 禁止。
- バウンス: 禁止。
- 画面サイズ差は相対レイアウトとスケーリングで吸収する。
- 庭は1枚の固定された景観として見せる。

## 全画面鑑賞
**暫定**
- 基本は固定。
- 必要ならごく軽い視差・カメラ揺れ・限定的ズームを将来検討。
- 通常のScrollView的な上下移動は行わない。

## ゾーン拡大観察
**確定方針**
- ゾーン内での限定的パン／ズームを許可してよい。
- 可動範囲はゾーン境界内に制限し、無限スクロールのようにはしない。
- 植物選択精度を上げるための操作として扱う。

## 編集モード
**確定方針**
- 植栽スポット操作に必要な範囲でパン／ズームを許可してよい。
- 編集対象がUIの下に隠れないようSafe Areaとトレイ占有領域を考慮する。

# 30. 実装順序 / Acceptance Criteria / Work Handoff

## Workへ渡す時の最優先原則
**確定**
- この仕様書をSingle Source of Truthとして扱う。
- 現行プロトタイプの見た目を完成版デザインの根拠にしない。
- **既存データ・検索・学習履歴等、再利用可能なロジックは捨てずに監査してから改修する。**
- 最終アートが未完成でも、仮素材で実装を進める。
- 不明点を推測で恒久仕様へ変えない。調整値は設定化し、判断が必要なものは実装報告へ明記する。
- 幽香の最終台詞を大量に独自作成しない。イベントIDと仮文でシステムを成立させ、正式台詞は後から差し替え可能にする。

## Phase 0 — リポジトリ / データ監査
**最優先**
1. 現行Xcodeプロジェクトがビルド可能か確認。
2. 307属マスターデータの格納形式・ID安定性を確認。
3. 現行ユーザーデータの保存形式を確認。
4. 既存の以下を「再利用 / 修正 / 廃棄」に分類:
   - 図鑑検索
   - 図鑑詳細
   - 3形式進捗
   - 写真
   - 学習履歴
   - 庭園データ
   - 植栽編集
5. 破壊的変更前にバックアップ方針を確立。
6. 監査結果を短いレポートとして残す。

**完了条件**
- 既存データを失わずに改修できる見通しが立っている。
- 旧データ→新スキーマの移行可否が項目別に分かっている。

## Phase 1 — データモデル / 設定値の分離
1. `schemaVersion` を導入。
2. マスターデータとユーザー進捗を分離。
3. 復習、庭園所属、表示スロット、写真、外観、イベント既読等の新データモデルを導入。
4. 調整値をコードへ直書きせず設定層へ移す。
5. 既存データ移行を実装。

**完了条件**
- 旧進捗が移行できる。
- パラメータ変更だけで復習間隔・スロット数・アニメ速度等を調整できる。

## Phase 2 — ナビゲーション / 共通デザイン基盤
1. 下部タブを `図鑑 / ホーム / 庭園 / 手入れ` へ整理。
2. 共通の色・文字・余白・ボタン・状態ラベルを定義。
3. ホームをScrollViewから外し、固定画面化。
4. 全画面鑑賞モードの入力状態を分離。
5. 起動画面と仮ロゴ / 仮アイコンを配置。

**完了条件**
- ホームが端末差で上下にバウンスしない。
- 現行の低コントラストUIを残さない。
- 全画面鑑賞時に誤ってゾーン遷移しない。

## Phase 3 — 庭描画基盤 技術スパイク
**実装前に小規模検証**
- SwiftUI内へSpriteKit等の2Dシーン描画基盤を組み込む。
- 仮の5頭身人型1体。
- 15個程度のインタラクティブ植物。
- 背景植生クラスター。
- z順、タップ判定、ピンチズーム、限定パン。
- CharacterAnchor間の滑らかな座標移動。
- 植物の微揺れ。

**完了条件**
- 実機で60fps相当のカメラ / キャラ座標移動が成立する。
- 15属前後の庭景観で選択精度が破綻しない。
- UIと庭の入力競合がない。

## Phase 4 — 中央庭園 / 観察 / 編集
1. 中央庭園の基本構図を仮素材で実装。
2. ホーム→ゾーン拡大観察。
3. 植物選択時の他植物低透明度化。
4. 幽香の観察Anchor入場。
5. 植栽編集モード。
6. 下部トレイ。
7. 長押し→ドラッグ＆ドロップ。
8. 配置判定（物理 / 環境 / 景観）。
9. 保存 / 破棄 / Undo基盤。

**完了条件**
- ホームで植物を触っても直接個体選択にならず、まずゾーンへ入る。
- 鑑賞モード中はゾーン / 植物タップが無効。
- 編集中だけ植栽スポットが見える。
- `完了` 前の変更が永続配置を壊さない。

## Phase 5 — 新規学習 / 問題UI / 入力
1. `咲かせる`。
2. 予習画面 + スキップ。
3. 共通問題画面。
4. 日本語 / 英字入力。
5. 採点正規化。
6. `正解 / 惜しい / 不正解`。
7. 1→2→3形式の成長。
8. 開花後の配置選択。

### 日本語入力の技術スパイク
- 正式問題中に予測候補から答えが見えない方式を実機検証する。
- iOS標準IMEで要件を満たせない場合は、アプリ内かな / フリック入力を採用する。

**完了条件**
- 予測候補に答えが露出しない。
- Enter / ↑↓のフォーカス移動が仕様通り。
- 途中終了しても確定済み回答が失われない。

## Phase 6 — 正式復習 / 手入れ / 状態劣化
1. 1/3/7/14/30/60/120日段階。
2. 正解 / 惜しい / 不正解ロジック。
3. 期限前自由復習。
4. `relearnedAt`。
5. 復習保護。
6. 今日の手入れ最大5属。
7. 開始前プレビュー。
8. 近日の手入れ。
9. `overdueSeverity` と5段階表示。
10. 庭上の退色連動。

**完了条件**
- 期限前は庭が基本正常に見える。
- 超過日数が増えるほど段階的に退色する。
- 図鑑を見るだけでは期限 / 退色が回復しない。
- 再学習直後の属をアプリがおまかせ復習へ自動提示しない。
- 期限超過しても復習件数が日数分増殖しない。

## Phase 7 — 図鑑 / 情報隠し / 演習
1. 既存307属検索を新UIへ統合。
2. 図鑑詳細。
3. 復習保護中の主要暗記項目伏せ。
4. `幽香に訊く`。
5. 情報隠しモード。
6. 演習セットアップ。
7. 即答オプション。
8. 演習履歴を正式復習履歴と分離。

**完了条件**
- 図鑑を開いただけでは再学習扱いにならない。
- 保護中に答えを明示的に開いた時だけ `relearnedAt` が付く。
- 演習正解だけで復習段階 / 開花進捗が進まない。

## Phase 8 — 庭園所属 / 区画解放 / 曖昧の庭
1. `assignedGardenID` と `displayZoneID` を分離。
2. 控え植栽。
3. 幽香管理 / ユーザー管理。
4. 区画解放キュー。
5. 自動移植の制限。
6. 曖昧の庭。
7. 遠景植生LOD。

**完了条件**
- 15属程度しか直接表示できなくても、所属植物が消失扱いにならない。
- ユーザー手動配置は幽香が勝手に移動しない。
- 曖昧の庭は本来の植物を移動させず「似姿」のみ表示する。

## Phase 9 — 写真 / 外観 / バックアップ / 通知
1. 写真永続保存。
2. 観察済み。
3. `appearanceVariants`。
4. 写真問題ボーナス。
5. バックアップ書き出し / 読み込み。
6. 通知。
7. 設定 / アクセシビリティ。

**完了条件**
- 写真が再起動で失われない。
- 外観バリエーションは実在範囲の候補だけ。
- 通知OFF時に通知しない。
- 1日複数回催促しない。

## Phase 10 — アニメーション / サウンド / 最終アート差し替え
1. 幽香仮素材でAction必要数を再確認。
2. 本番アート発注仕様を確定。
3. 歩行 / 待機 / 座る / 花を見る / 手入れ。
4. 植物微揺れ。
5. 水面。
6. BGM / 環境音。
7. Logo A / Icon A方向の最終データへ差し替え。

**完了条件**
- 本番アート差し替えでロジック変更が不要。
- `アニメーションを減らす` 設定でも操作意味が失われない。

## 全体Acceptance Criteria
**必須**
- ホームは固定画面で、意図しない縦スクロール / バウンスなし。
- 庭がUIカードの背景ではなく画面の主景観。
- 通常ホーム / 鑑賞 / 観察 / 編集の入力状態が明確に分離。
- 307属データを保持。
- 確定済み学習進捗をアプリ更新・強制終了で失わない。
- 開花前の成長と開花後の正式復習を混同しない。
- 演習だけで正式復習段階が進まない。
- 正式復習期限前に庭を恒常的に退色させない。
- 期限超過タスクを日数分積み上げない。
- おまかせ復習は1セット最大5属。
- 図鑑を開いただけで「今日の復習が無効」にならない。
- 復習保護中でも答えを見たいユーザーをロックアウトしない。
- 主要状態は色だけに依存しない。
- ユーザー手動配置を自動で勝手に動かさない。
- 家具自由配置はv1に含めない。
- AI生成画像を本番の幽香アートとして前提にしない。
- 現行プロトタイプの低コントラストUIを完成版として流用しない。

## 実装を止めない「未確定 / 調整項目」
以下は**ブロッカーではない**。設定値または仮素材で進める。
- 復習保護開始時間の最終値。
- `惜しい` 15〜20%の最終閾値。
- `overdueSeverity` 境界の微調整。
- 各庭園の最終スロット数。
- 区画解放閾値。
- 幽香の最終台詞。
- 幽香の本番アート。
- 各307属の最終植物アセット。
- BGM曲そのもの。
- Logo A / Icon Aの最終清書。

## Workから実装報告してほしい技術判断
以下は仕様を勝手に変えず、採用方式と理由を報告する。
- SwiftUI + SpriteKit等、庭描画基盤の最終選定。
- 日本語予測変換を防ぐ入力方式。
- 現行データ移行方式。
- 写真ファイルの保存方式。
- バックアップ形式。
- 端末性能別LOD方針。

## Handoff成果物
Workの各主要フェーズ終了時に最低限以下を残す。
- ビルド可能なコード。
- 変更点の短い実装メモ。
- データ移行に影響がある場合は移行メモ。
- 実機 / シミュレータの主要画面スクリーンショット。
- 既知の未実装 / 仮素材 / TODO。
- 仕様から変更した箇所がある場合、その理由。
